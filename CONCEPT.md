# Ledgerly-Rust: concept

What Ledgerly-Rust is, how it is built, and what "done" means. *What Ledgerly does* is defined by [Ledgerly-Java's concept](vendor/ledgerly-java/CONCEPT.md) §1 and §4 and is not repeated here. Read those sections first. Vocabulary follows [`GLOSSARY.md`](GLOSSARY.md); where this document and the glossary disagree, the glossary wins.

## 1. The project

Ledgerly-Rust is a **drop-in replacement** for Ledgerly-Java at the vendored commit ([ADR 0005](docs/adr/0005-drop-in-replacement-on-the-same-data.md)). The following must be indistinguishable from Java to a client, an operator or the database:

| Surface | Defined by | Rust may not change |
| --- | --- | --- |
| HTTP API | `api/openapi.yaml` + Java behaviour | paths, shapes, status codes, headers, error `code`s, paging and cursor formats, ETags |
| Database | `vendor/ledgerly-java/src/main/resources/db/migration/` | anything; applied by Flyway unchanged ([ADR 0006](docs/adr/0006-apply-java-migrations-unchanged-with-flyway.md)) |
| Stored data | Java code | password hash format, token hashing, idempotency records, storage keys, audit `details` JSON |
| Tokens | Java code | ES256, claims, `kid`, JWKS, refresh cookie |
| Configuration | Java `application*.yaml`, `.env.example` | variable names, profiles, defaults, fail-fast in `prod` ([ADR 0013](docs/adr/0013-java-configuration-and-operational-contract.md)) |
| Operations | Java `docs/deployment.md` | ports 8080/8081, `/actuator/*` paths, graceful shutdown, ECS JSON logs |
| Demo data | [`docs/reference/demo-data.md`](docs/reference/demo-data.md), from Java's `DevDataSeeder` | team id, users, passwords, memberships, invitation, expenses |

Two exceptions are accepted ([ADR 0005](docs/adr/0005-drop-in-replacement-on-the-same-data.md#accepted-exceptions), [deployment runbook](docs/deployment.md#switching-between-java-and-rust)):
- Events left unfinished by one implementation are not replayed by the other.
- Idempotency request hashes are computed differently, so within 24 hours of a switch a retry may get 422 instead of a replay.

Everything *inside* that boundary is designed afresh in idiomatic Rust: types, error handling, concurrency, module boundaries. That's where the learning happens ([`MISSION.md`](MISSION.md)).

## 2. Tech stack

| Concern | Choice | Replaces in Java | Why |
| --- | --- | --- | --- |
| Language | Rust stable, edition 2024, pinned in `rust-toolchain.toml` | Java 25 | — |
| Async runtime | tokio | virtual threads | The ecosystem default; everything below builds on it |
| HTTP | axum + tower + tower-http ([ADR 0008](docs/adr/0008-tokio-axum-sqlx.md)) | Spring MVC, filter chain | Tower layers map one-to-one onto Spring Security filters |
| API contract | Server traits and models generated by openapi-generator `rust-axum` into `crates/api` ([ADR 0009](docs/adr/0009-server-traits-generated-from-openapi.md)) | openapi-generator `spring` | Same compile-time guarantee as Java's generated interfaces |
| Database | PostgreSQL 17, sqlx with compile-time-checked queries, offline metadata in `.sqlx/` | JPA/Hibernate, JdbcClient | The schema is owned by Flyway; SQL stays visible |
| Migrations | Flyway container, Java's SQL unchanged ([ADR 0006](docs/adr/0006-apply-java-migrations-unchanged-with-flyway.md)) | Flyway in-process | Identical schema by construction |
| Money | `rust_decimal::Decimal` + ISO 4217 table, in a `Money` newtype | `BigDecimal` + `java.util.Currency` | Exact decimal arithmetic. The currency table must match Java's `Currency` fraction digits |
| Ids | `uuid` v7 in newtypes (`ExpenseId`, `TeamId`, …) | records wrapping `UUID` | — |
| Serialization | serde, serde_json | Jackson | Unknown properties are rejected (`deny_unknown_fields`) like Java's `fail-on-unknown-properties` |
| Validation | Explicit constructors returning `Result` (parse, don't validate), plus generated model constraints | Bean Validation | Invalid values cannot exist past the HTTP edge |
| Errors | `thiserror` enums per module → one `ProblemDetail` mapper | sealed exceptions + `@RestControllerAdvice` | Exhaustive `match` instead of exception handlers |
| Passwords | `argon2` (RustCrypto), PHC string with Spring's parameters | Spring `Argon2PasswordEncoder` | Hashes interchangeable with Java |
| JWT | `jsonwebtoken` (ES256) + `p256` for keys and the RFC 7638 thumbprint | Nimbus | — |
| Secrets in memory | `secrecy` + `zeroize` | — (new) | Redacted in `Debug`, wiped on drop |
| Object storage | `aws-sdk-s3` (presigned GET) | AWS SDK v2 | — |
| File type sniffing | `infer` (magic bytes) | Apache Tika | Only PDF, JPEG, PNG must be recognised |
| Malware scan | Own clamd `INSTREAM` client on `tokio::net::TcpStream`, with retry | Own client + `@Retryable` | Same as Java |
| Batch and import | tokio tasks, `csv` crate, job state in `import_jobs` | Spring Batch | `BATCH_*` tables stay unused ([ADR 0006](docs/adr/0006-apply-java-migrations-unchanged-with-flyway.md)) |
| Events | Transactional outbox in `event_publication` + in-process dispatcher, republished on restart | Spring Modulith registry | Same table, Rust's own event types ([ADR 0005](docs/adr/0005-drop-in-replacement-on-the-same-data.md)) |
| Rate limiting | `governor` (GCRA), in memory, per user and per IP | Bucket4j | `Retry-After` must match Java's semantics (see plan M10) |
| Logging and telemetry | `tracing`, an ECS JSON formatter, `opentelemetry-otlp`, Prometheus metrics on 8081 | Logback ECS, Micrometer | Same log fields, same metric names |
| Config | Environment variables under Java's names, parsed into typed structs at startup | `@ConfigurationProperties` | — |
| Tests | `cargo-nextest`, `testcontainers`, `reqwest` for the parity suite, `jsonschema` for response validation | JUnit, Testcontainers, `RestTestClient` | — |
| Quality and supply chain | rustfmt, clippy (`-D warnings`, no `unwrap`/`expect`/`panic` outside tests), `cargo-deny`, `cargo-auditable`, CycloneDX SBOM, Trivy, gitleaks, Renovate | Spotless, NullAway, enforcer, Trivy, gitleaks, Renovate | — |

These crates are the plan's defaults. Replacing one is fine if the commit says why, `cargo deny` passes, and the learning log records it. A choice with ADR status (axum, sqlx, generated traits, Flyway) needs a new ADR.

## 3. Architecture: a modular monolith as a Cargo workspace

One binary, six business modules plus `shared`, the same modules and allowed dependencies as Java (Java plan §2). Each is a crate ([ADR 0010](docs/adr/0010-one-crate-per-module.md)):

```text
Ledgerly-Rust/
├── Cargo.toml                  workspace; shared lints: forbid(unsafe_code), clippy denies
├── rust-toolchain.toml, mise.toml, justfile, deny.toml
├── crates/
│   ├── api/                    GENERATED from api/openapi.yaml; never edited by hand
│   ├── shared/                 Money, typed ids, ProblemDetail + error catalogue, paging, cursor,
│   │                           idempotency, ETag, clock, config, current-user extractor, outbox
│   ├── identity/               users, passwords, verification, refresh tokens, JWT, JWKS
│   ├── teams/                  teams, memberships, roles, invitations, /me
│   ├── expenses/               Expense aggregate, workflow, list/export, batch
│   ├── receipts/               upload, scan, storage, download; implements expenses::ReceiptChecks
│   ├── imports/                CSV import jobs
│   ├── audit/                  append-only audit trail from everyone's events
│   ├── app/                    the `ledgerly` binary: config, wiring, router, layers, seeding, shutdown
│   └── parity-tests/           black-box HTTP suite, runnable against any base URL (ADR 0011)
├── .sqlx/                      offline query metadata (committed)
├── Dockerfile, compose.yaml, .env.example
├── docs/ (adr/, implementation-plan.md, learning-log.md, local-setup.md, deployment.md)
├── api/openapi.yaml, redocly.yaml, bruno/   shared with Java, read-only (ADR 0007)
└── vendor/ledgerly-java/       other shared files, read-only: migrations, config, realm, Java docs (ADR 0007)
```

Allowed dependencies between crates (identical to Java's arrows):

```text
            shared  ◄──────────── everyone
               ▲
identity ◄── teams ◄── expenses ◄── receipts
                           ▲
                           └────── imports ──► teams
audit ──► events of identity, teams, expenses, receipts, imports
app ──► everything (wiring only)
```

Java's audit module authorizes its endpoint through the teams module by bean name, which avoids a code import. In Rust, `shared` owns a small `TeamRoles` trait, `teams` implements it and `app` injects it. That way audit still depends only on `shared` and on events.

[`docs/reference/java-port-spec.md`](docs/reference/java-port-spec.md) maps every module's facade, events, listeners, error catalogue, configuration properties, crypto and encoding details, and background flows, with paths into the vendored Java. Read it before porting a module.

Inside each module crate:

```text
crates/expenses/src/
├── lib.rs           pub: ExpensesFacade, events, ReceiptChecks, ReceiptSummary; nothing else
├── events.rs        pub: ExpenseSubmitted, …
├── domain/          aggregate, status, policies: pure, no I/O, no async
├── application/     use cases: take a transaction, call the domain, write events to the outbox
├── persistence/     sqlx queries; every read is team-scoped
└── web/             implements the generated trait(s) from `api`, maps DTOs ↔ domain
```

Rules, enforced by the compiler where possible:

1. A crate's public items are only its facade, its events and the interfaces it owns ([Java ADR 0002](vendor/ledgerly-java/docs/adr/0002-expenses-asks-receipts-through-an-interface-it-owns.md)). Everything else is `pub(crate)`. A test in `app` checks the workspace dependency graph against the arrows above.
2. A module never touches another module's tables. Commands go through the owning module's facade and everything else reacts to events ([Java ADR 0003](vendor/ledgerly-java/docs/adr/0003-commands-through-facades-not-only-events.md)).
3. Events are written to `event_publication` in the same transaction as the change that caused them. A dispatcher delivers them after commit, and unfinished ones are delivered again on restart.
4. `domain/` is synchronous and I/O-free. Time comes in as a `Clock` trait object, never from `SystemTime::now()` directly.

## 4. Security by design

Security is the top priority. Every control Java has is carried over and has a test that tries to break it. Rust adds controls Java couldn't express. The checklist is the [OWASP API Security Top 10 (2023)](https://owasp.org/API-Security/editions/2023/en/0x11-t10/).

### Principles

- **Deny by default.** The router has one public allowlist: `/auth/**`, the JWKS endpoint, and `/docs` only in `local`. Every other route sits behind the authentication layer. Management endpoints live on a separate listener (8081).
- **Tenant scoping in the data layer.** Every persistence function that reads team data takes a `TeamId`. No unscoped "find by id" exists, so one can't be called by mistake. Membership is checked before the query runs. A non-teammate gets 404, a teammate with the wrong role 403.
- **Parse, don't validate.** Request DTOs are converted into domain types whose constructors enforce every invariant (`Money`, `Email`, `Merchant`, …). An invalid value can't exist past the HTTP edge, and nothing sets `status` or `claimantId` from the request (mass assignment is impossible by construction).
- **Limits everywhere.** Page 100, batch 100, upload 10 MB (counted while streaming, plus a body limit at the edge), import 10,000 rows and 5 per day, per-user and per-IP request rates, login lock. All of them come from one `Limits` config struct.
- **Secrets are a type.** Passwords, tokens, keys and credentials are `SecretString`/`SecretBox` from the moment they're read. They can't be logged by accident and are zeroed on drop.
- **Memory safety is not optional.** `#![forbid(unsafe_code)]` in every crate of ours. Dependencies are checked by `cargo-deny` for advisories, licences, duplicates and sources.
- **No panics in request paths.** Clippy denies `unwrap`, `expect`, `panic!`, indexing that can panic, and arithmetic overflow in `domain/`. A panic that still happens is caught by a tower layer and answered with a generic 500 carrying only the trace id.
- **Secrets never in Git.** Config comes from the environment. `.env` is git-ignored and `.env.example` documents every key. gitleaks runs in pre-commit and in CI.
- **Supply chain.** Images and CI actions are pinned by digest or SHA. Renovate waits 3 days before proposing a new release. The binary is built with `cargo auditable`, and the image is scanned by Trivy and ships with a CycloneDX SBOM. The image runs non-root, read-only, with no capabilities and no shell ([ADR 0012](docs/adr/0012-distroless-runtime-image.md)).

### OWASP API Top 10 mapping

Same controls and proving tests as [Java's table](vendor/ledgerly-java/CONCEPT.md) §5. Each row is one module of the parity suite (`crates/parity-tests/tests/owasp_api<N>_*.rs`), ported from `https://github.com/AlexisRoe/Ledgerly-Java/blob/e2a13909634808b347d30b3dec4c3ffee6741c02/src/test/java/com/ledgerly/owasp/`.

| OWASP risk | Control in Ledgerly-Rust | Rust-specific addition |
| --- | --- | --- |
| API1 Broken object level authorization | Team-scoped persistence functions; membership check in every use case; MEMBERs see only their own | Persistence API takes `TeamId` by type, so an unscoped query does not compile |
| API2 Broken authentication | Argon2id; 10-min ES256 JWTs; refresh rotation with family revocation on reuse; login rate limit and lock; verified email to accept invitations | Secrets in `secrecy` types; constant-time comparison of token hashes (`subtle`) |
| API3 Broken object property level authorization | Separate request/response types; `status`, `claimantId` not writable | Generated request structs have no such fields; `deny_unknown_fields` |
| API4 Unrestricted resource consumption | Page/batch/upload/import caps, per-user and per-IP limits with `Retry-After` | `tower_http::limit::RequestBodyLimitLayer` at the edge and a streaming byte counter |
| API5 Broken function level authorization | Role ladder checked in every use case | `Role` comparisons via an exhaustive `match`; authorization result is a typed `Actor` the domain requires |
| API6 Sensitive business flows | No self-dealing; invitations don't reveal registered emails; 5 imports per day | — |
| API7 SSRF | No feature fetches user-supplied URLs; outbound connections only to configured hosts | Only `*/infrastructure` modules may depend on HTTP/socket crates, checked by a workspace test and `cargo-deny` bans |
| API8 Security misconfiguration | Security headers, exact CORS allowlist, management on 8081, no docs outside `local`, no stack traces in errors | `prod` startup refuses missing config and listener misconfiguration |
| API9 Improper inventory management | The OpenAPI file is the inventory; served routes = spec paths | Routes come from the generated trait, and a test compares the router with the spec |
| API10 Unsafe consumption of APIs | CSV input and clamd responses are untrusted; CSV export neutralises formula cells | Parsers return `Result`; no panicking indexing on untrusted input |

## 5. Errors, logging, observability

Wire behaviour is exactly Java's ([Java concept §6](vendor/ledgerly-java/CONCEPT.md)): RFC 9457 `application/problem+json` with the `type`, `title`, `status`, `detail`, `instance`, `code`, `traceId` and `errors` fields, and the same error catalogue (`https://github.com/AlexisRoe/Ledgerly-Java/blob/e2a13909634808b347d30b3dec4c3ffee6741c02/src/main/java/com/ledgerly/shared/error/ErrorCatalogue.java`). Responses Spring generated implicitly (404 for unknown routes, 405, 415, malformed JSON) must be reproduced too.

- **Errors in Rust:** each module has a `thiserror` enum. `shared` maps every variant to a catalogue entry with one exhaustive `match`, so adding a variant without deciding its HTTP mapping doesn't compile. An unknown error becomes a 500 that carries only the `traceId`.
- **Logs:** ECS JSON on stdout in every profile except `local`, with the field set Spring Boot's `ecs` structured-logging format writes (`@timestamp`, `log.level`, `message`, `ecs.version`, `service.name`, `log.logger`, `process.thread.name`, plus MDC entries such as `traceId`, `spanId`, `userId` and `teamId`). M1 pins the exact list in a test. The same things are never logged: passwords, tokens, cookies, `Authorization`, file contents, request bodies.
- **Metrics and traces:** OTLP export to the Grafana LGTM container. Prometheus format on `:8081/actuator/prometheus`, with Java's custom metric names (`ledgerly.receipts.quarantined`, `ledgerly.imports.rows.skipped`, `ledgerly.expenses.transitions{action}`). Spans around S3 and clamd calls.
- **Audit trail:** separate from logs. An append-only table filled from events, made immutable by the database itself (V8).

## 6. Testing

| Layer | Where | What it proves |
| --- | --- | --- |
| Unit | `#[cfg(test)]` in each crate, mostly `domain/` | Invariants and the state machine, without I/O. Property tests (`proptest`) for `Money` and the transition table |
| Integration | `crates/<module>/tests/`, testcontainers Postgres migrated by the Flyway container | SQL, transactions, locking, outbox, team scoping |
| Parity (acceptance) | `crates/parity-tests/` + the vendored Bruno collection ([ADR 0011](docs/adr/0011-black-box-parity-suite.md)) | Black-box behaviour equals Java's: every endpoint, error, header and OWASP row. State is set up with SQL fixtures in the shared schema and environment variables, never with test endpoints. Responses are validated against `openapi.yaml` |
| Time and fault behaviour | `crates/<module>/tests/` with an injected `Clock` | Expiry, lockout, daily limits, the unexpected-error 500, scanner outages: Java tests that moved a clock or injected a fault, ported in-process |
| Architecture | `crates/app/tests/architecture.rs` | Crate dependency graph matches §3; only infrastructure modules use network crates |
| Log hygiene | parity suite + log capture of the running container | No email, token, password or cookie in any log line |

The parity suite starts out complete and **ignored**. Every parity test is ported up front (plan M1) and marked `#[ignore = "M<N>"]` with the milestone that makes it pass. A milestone is only done when all of its tests are un-ignored and green. `just parity` prints how many are still ignored, which is the project's progress meter.

## 7. Local setup and delivery

See [`docs/local-setup.md`](docs/local-setup.md) (install OrbStack and mise, then `mise install && pre-commit install && just up`) and [`docs/deployment.md`](docs/deployment.md).

CI (GitHub Actions, on every push to any branch): `verify` (`just check`) and `parity` (`just parity`), which together are `just verify`, `openapi-lint`, `format-config`, `gitleaks` over the full history, `deny`, `vendor-drift`, and `image`, which builds the image, checks that it runs as non-root, scans it with Trivy and uploads the SBOM. Actions are SHA-pinned, the token is `contents: read`, and checkouts use `persist-credentials: false`. A scheduled weekly job reports whether Ledgerly-Java has moved past the vendored commit; it doesn't fail the build.

## 8. How work proceeds

An agent implements [`docs/implementation-plan.md`](docs/implementation-plan.md) under the rules in [`CLAUDE.md`](CLAUDE.md):
- one step at a time, each ending with a green `just verify` and one commit on the current branch;
- one learning-log entry per milestone;
- a stop for review after every milestone.

Nothing is pushed by the agent.

### Definition of done (every milestone)

- [ ] `just verify` is green: fmt, clippy, deny, generated code up to date, unit + integration + architecture tests, vendor drift check.
- [ ] Every parity test assigned to this milestone is un-ignored and passes; no parity test was weakened.
- [ ] Every new endpoint has at least one abuse test (wrong team 404, wrong role 403, invalid input 400, wrong state 409, stale `If-Match` 412, whichever apply).
- [ ] No secrets, tokens or personal data in logs or Git history.
- [ ] No `unsafe`, no new `unwrap`/`expect` outside tests, no unexplained new dependency.
- [ ] The learning-log entry is written, and the agent has stopped for review.

## 9. Out of scope

- Any change to behaviour, contract or schema relative to the vendored Java. Those happen upstream first.
- Replaying the other implementation's in-flight events.
- Spring Batch's `BATCH_*` tables (they exist, unused).
- Lessons. They're written after M11 from the learning log.
- Everything Java declares out of scope: a frontend, real payments, real email delivery, account deletion (Java ADR 0001).
