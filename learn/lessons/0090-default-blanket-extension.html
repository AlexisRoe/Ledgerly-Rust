Traits in depth

Default methods, blanket impls, extension traits

Three ways to add behaviour to many types at once: write it once in the trait, implement the trait for every type that meets a bound, or attach new methods to a type you don't own.

By the end of this lesson

You can read impl<T: Display> ToString for T, write a default method and an extension trait, and recognise a decorator written as a generic impl.

2. Blanket impls

An impl can be generic over the implementing type itself:

That's why 42.to_string(), expense_id.to_string() and status.to_string() all work, although nobody wrote ToString for those types. Other blanket impls you use daily: impl<T, U: From<T>> Into<U> for T (why implementing From gives you .into()) and impl<I: Iterator> IntoIterator for I (why every iterator works in for). ?Sized lifts the default "size known at compile time" bound, so the impl also covers str and dyn Trait.

3. Extension traits

Unlike prototype patching, it's scoped: the method only exists where the trait is imported. That's also why you sometimes need use std::fmt::Write as _; or use tower::ServiceExt; before a method "appears" (lesson 49). Crates name them …Ext by convention: FutureExt, ServiceExt, SinkExt.

In Ledgerly: a decorator as a generic impl

It wraps any metrics recorder and is itself a recorder, renaming counters on the way through: the decorator pattern, with the wrapped type known at compile time.

Where the comparison breaks

A blanket impl is a promise for all types, including future ones, so it blocks other impls that could overlap. Once std has impl<T: Display> ToString for T, no one can write a separate ToString for a type that's also Display. Coherence (next lesson) is the set of rules that keeps such overlaps impossible.

Check yourself

Why does status.to_string() work on ExpenseStatus?

  • Every enum gets to_string from its derive list
  • It implements Display, and a blanket impl adds ToString
  • The compiler generates to_string for all public types
  • ExpenseStatus has a hand-written to_string method in it
impl<T: Display + ?Sized> ToString for T in std.

An extension method isn't found (E0599), though the trait is implemented. Likely cause?

  • Extension traits only work on types from std
  • The trait isn't imported with use in this file
  • The method must be marked pub(crate) as well
  • Extension traits need a derive on the type
Trait methods are only callable where the trait is in scope.

What does ?Sized in impl<T: Display + ?Sized> allow?

  • T may be a type that has no Display impl
  • T may be unsized, like str or dyn Trait
  • T may be any size, but only behind Box
  • T may be optional, so the impl can skip it
Generic parameters are Sized by default; ?Sized relaxes that.
