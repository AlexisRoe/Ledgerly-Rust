Traits and generics

Generics with trait bounds

<T extends Something> becomes <T: Something>. Bounds are traits, and they say exactly which operations the generic code may use on T.

Same idea, different keyword

  • T: Ord + Copy: T must implement both traits; + combines bounds.
  • Without a bound you can do almost nothing with a T: no ==, no printing, no copying. The compiler only allows what the bounds promise (Book 10.2, "Trait Bound Syntax").
  • x: impl Display in a parameter is shorthand for a generic with that bound (lesson 44's impl Into<String>). In a return position, -> impl Fn(&str) -> String means "some concrete type that implements this, which I won't name".

where clauses for long bounds

How Ledgerly registers an endpoint. Read the where clause as requirements:

  • H: Handler<T, S>: the handler can be any function that axum knows how to call as a request handler (axum implements Handler for async functions with suitable arguments).
  • S: Clone + Send + Sync + 'static: the state (e.g. ExpensesApi) must be cloneable per request, safe to share across threads, and contain no short-lived borrows ('static as a bound means "owns everything it holds").

You don't need to understand axum's Handler to read this: the bounds say what the function needs, and that's the point.

Generic types and generic impls

"For every hasher type S, a HashMap<&str, &str, S> is an Environment." The impl<…> introduces the type parameter, and the bound restricts it.

Where the comparison breaks

TS generics are erased and checked structurally. Rust generics are monomorphized: the compiler generates a separate copy of largest for each T it's used with (lesson 27). That makes them as fast as hand-written code, at the cost of compile time and binary size. When you need one piece of code to handle many types at runtime, for example "whatever clock was configured", you use a trait object instead. That's the next lesson.

Check yourself

What's the Rust for <T extends A & B>?

  • <T: A, B>
  • <T: A & B>
  • <T: A + B>
  • <T extends A + B>
Bounds are combined with +.

A generic function compares two Ts with == but has no bound. What happens?

  • It works; every type supports equality checks
  • Compile error: T needs a PartialEq bound first
  • It compares the memory addresses of the values
  • It panics at runtime for types without equality
Generic code may only use what the bounds promise. The error suggests T: PartialEq.

In S: Clone + Send + Sync + 'static, what does 'static require?

  • S must be a global static variable
  • S holds no borrowed references that expire
  • S must be created at compile time
  • S lives on the stack, never the heap
As a bound, 'static means "contains no non-static references", so the router can keep it for as long as the server runs.
