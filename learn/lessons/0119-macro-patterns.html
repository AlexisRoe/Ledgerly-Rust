Writing macros

Repetition, internal rules and hygiene

Three techniques cover most real macros: recursion for variable-length input, internal @rules for shared code, and generating whole items such as test functions. And one property protects you from the classic macro bug: hygiene.

Hygiene

A local variable created inside a macro lives in the macro's own syntax context. It can't capture or shadow the caller's variable of the same name, and the caller's code can't see it. So let result = 10; double_it!(result + 1) works even if double_it! declares its own result. Hygiene covers local variables and labels; item names (functions, types) are not hygienic, which is exactly what lets typed_id! define UserId for the caller.

Where the comparison breaks

Code generators in the JS world produce text files that you then commit or build. Rust macros run inside the compiler, on every build, with errors pointing into the macro call. The trade-off: macro errors can be hard to read, and rust-analyzer's help (completion, go to definition) is weaker inside macro bodies.

Check yourself

In typed_id!, what is @common?

  • A keyword that makes the rule fully private
  • A literal token that marks an internal rule
  • An attribute telling the compiler to share code
  • A reference to a separate macro named common
Any token works; @ is used because normal callers won't start with it.

Why generate one test per table row instead of a loop in one test?

  • Because loops aren't allowed inside test functions at all
  • Each row passes or fails under its own name
  • Because generated tests run faster than plain loops
  • So that the table can be read at runtime
The first failing row doesn't hide the others, and the report names the case.

A macro declares let total = 0;. The caller also has a total. What happens?

  • The macro's total overwrites the caller's own variable
  • Nothing clashes; each total has its own context
  • A compile error about a duplicate variable name
  • The caller's total is used inside the macro
Hygiene: local names from different syntax contexts never collide.
