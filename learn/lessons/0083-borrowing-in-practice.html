Ownership and lifetimes in depth

Borrowing in practice

The borrow checker is smarter than its rule of thumb suggests. Knowing exactly what it tracks (fields, last use, map entries) turns most "fights" into a pattern you already know.

By the end of this lesson

You can fix the four most common borrow errors in real code: borrowing self in a loop over one of its fields, "get or insert" on a map, two &mut into one slice, and a borrow held too long.

What do E0499 and E0502 say?

2. Fields are tracked separately; methods borrow everything

Inside one function the compiler sees self.members, self.name and self.log as separate places. A method's signature only says &self, so calling it borrows the whole struct. Fixes: borrow the fields you need, make the helper a free function taking just those fields, or split the struct.

3. Maps: the entry API

The "if missing, insert, then get" dance is awkward with borrows and does extra lookups. entry returns a handle to the slot (occupied or vacant) and gives you a &mut to the value (std: Entry).

4. Two &mut into one collection

let a = &mut v[i]; let b = &mut v[j]; fails even if i != j: indexing is a method call, and the compiler can't prove the indexes differ. Ask the slice to check it for you: v.get_disjoint_mut([i, j]) returns both or an error, and v.split_at_mut(mid) splits a slice into two non-overlapping halves (Nomicon: splitting borrows). Or use v.swap(i, j) if that's all you need.

5. When all else fails: copy the value out

If you only need a small value from a borrow, copy or clone it into a local and let the borrow end: let id = expense.id; (it's Copy). Cloning a short String to escape a borrow is acceptable in application code; reach for it after the patterns above.

Check yourself

Why does calling self.label(m) inside for m in &self.members while pushing to self.log fail?

  • Methods can never be called inside for loops
  • Pushing needs &mut while label borrows all self
  • label returns a String, which can't be pushed
  • The for loop moved self.members out of self
Pushing mutably borrows self.log, and calling label borrows all of self at the same time, which includes log.

Best way to append to a list in a HashMap<String, Vec<u32>>, creating it if needed?

  • if !m.contains_key(k) { m.insert(…) }, then get_mut
  • m.entry(k).or_default().push(x)
  • m.get(k).unwrap().push(x)
  • m.insert(k, vec![x])
One lookup, no unwrap, works whether the key exists or not.

let a = &items[0]; items.push(x); println!("{a}"); Why is this rejected?

  • Indexing with zero is never allowed in Rust
  • push may reallocate while a is still used
  • println cannot print a borrowed String value
  • items must be declared static to be indexed
The shared borrow is still alive at the println!. Move the print up, and it compiles.
