Warm-up
What are the three standard pieces Ledgerly puts on every plain enum?
ALL (every variant), as_str (wire name via match), and Display/FromStr for text in and out.
Why does adding a variant break as_str?
match must cover every variant. The missing one is a compile error.

The discriminated union you know

(The /// docs are left out here, and the #[error(…)] attributes are thiserror's messages, covered in .) The three shapes a variant can have:

ShapeDeclaredBuilt
unitDeleted,ExpenseEventKind::Deleted
tuple-likeRuleViolated(&'static str),ExpenseError::RuleViolated("Receipts are still being scanned")
struct-likeSelfDealing { action: Action },ExpenseError::SelfDealing { action }

The tag (kind in TS) is implicit: the variant is the tag. Unlike TS, the variants' fields can't be read until you've checked which variant you have.

Getting the data out: match

This is how every domain refusal becomes an HTTP response. Each arm is a pattern:

  • ExpenseError::Forbidden(forbidden) matches that variant and binds its inner value to the name forbidden, like narrowing in a TS case, but the binding is created right in the pattern.
  • { .. } means "this variant, I don't need its fields".
  • There's no default/_ arm, on purpose. Add a variant to ExpenseError and this function stops compiling until you decide its HTTP status. The file's doc comment says exactly that.
In Ledgerly: mixed shapes in one enum

Only Edited needs extra data, so only it carries a field. There's no changedFields?: string[] that is "sometimes undefined".

Where the comparison breaks

In TS the discriminated union is a pattern you assemble from object types plus a convention (the kind field). Exhaustiveness needs the never trick. In Rust it's one language feature: the compiler knows every variant, a match must handle all of them, and you can't access a variant's fields without matching first. The next two lessons show that Option and Result are just enums of this kind.

Check yourself

How do you build the "self-dealing on approve" error?

  • ExpenseError::SelfDealing(Action::Approve)
  • ExpenseError::SelfDealing { action: Action::Approve }
  • ExpenseError { kind: SelfDealing, action: Approve }
  • new ExpenseError.SelfDealing(Action::Approve)
SelfDealing is declared struct-like, { action: Action }, so it's built with named fields.

In ExpenseError::RuleViolated(rule) => …, what is rule?

  • A new variable holding the whole error value
  • A new variable bound to the variant's message
  • An existing variable that is compared against it
  • The variant's name written out as a string
Names inside a pattern create bindings. rule is the &'static str inside the variant (here borrowed, so *rule reads it).

Why does refusal have no catch-all _ => arm?

  • Rust doesn't allow catch-all arms on error enums
  • So new variants fail to compile until mapped
  • Catch-all arms would make the function run slower
  • thiserror generates the missing arms automatically at build
With _, a new error kind would silently fall into a default HTTP status. Without it, the compiler forces a decision.
