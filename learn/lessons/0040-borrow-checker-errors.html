Ownership and borrowing

Reading the borrow checker's errors

Six error codes cover nearly everything you'll hit when you change Ledgerly. Each has a usual cause and a usual fix, and the compiler's message tells you most of it.

By the end of this lesson

Given a borrow-checker error, you can name what went wrong in one sentence and pick the right fix: reorder, borrow instead of move, add mut, shorten a borrow, or (last resort) clone.

Warm-up
State the borrow rule.
Any number of & or exactly one &mut, and no reference may outlive its value. (39)
What do you need before calling a &mut self method?
A mutable binding: let mut x. (39)

Borrows end at their last use

A borrow lasts until the reference is used for the last time, not until the end of the block. So reordering often fixes E0502/E0499:

How to read a full message

  1. The first line names the rule that was broken.
  2. The - and ^ labels are a timeline: borrow starts, conflict, borrow still used.
  3. Look for help: lines. They often contain the exact fix.
  4. rustc --explain E0502 prints a full explanation with examples, offline.
Where the comparison breaks

tsc errors are about types; borrow errors are about time: who has access when. The instinct from TS is to fight them with casts. Here the equivalent instinct is .clone() everywhere. It works, but first ask whether the value should be borrowed, or whether two lines should swap. Nearly every borrow error in Ledgerly-style code is fixed by one of those two.

Check yourself

You write let expense = load()?; expense.approve(actor)?;. Which error?

  • E0382: use of moved value
  • E0596: cannot borrow as mutable
  • E0499: two mutable borrows
  • E0597: does not live long enough
approve takes &mut self, so the binding must be let mut expense.

A helper returns &str pointing into a String it created locally. What's the right fix?

  • Add a 'static lifetime to the return type
  • Return the String itself, giving its ownership away
  • Wrap the local String in a Box first
  • Clone the &str just before it is returned
The local String is dropped when the function returns, so no borrow of it can escape. Return the owned value instead.

What's usually the first thing to try on E0502?

  • Add .clone() to the value that's being borrowed
  • Finish using the reader before the write happens
  • Wrap the value in an Arc and a Mutex
  • Mark the function unsafe to skip the check
Borrows end at their last use, so reordering often removes the overlap. (And unsafe is forbidden in Ledgerly anyway.)
