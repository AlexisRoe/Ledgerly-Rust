The three ownership rules and the borrow rule.
One owner; one at a time; dropped at end of scope. Many & or one &mut, and no reference outlives its value. (36, 39)
When is a value copied instead of moved?
When its type is Copy: numbers, bool, ids, Actor, Money, plain enums, shared references. (38)
What does dropping an uncommitted sqlx transaction do?
Rolls it back. (36)
Box, Rc, Arc: one line each.
Heap, one owner; many owners, one thread; many owners, any thread. (42)

Mixed questions

Does this compile?

  • No, E0382: id was moved into a already
  • Yes, ExpenseId is Copy, so it's copied twice
  • No, E0499: two mutable borrows of the id
  • Yes, but a and b share one id
Ids derive Copy. With a String instead, it would be E0382.

Does this compile?

  • No, E0382: merchant was moved into new
  • Yes, to_owned copies the text; merchant stays
  • No, E0502: merchant is still borrowed by new
  • Yes, because Merchant is a Copy type
as_str() borrows briefly, to_owned() makes a new String for the struct. merchant is untouched.

Which signature would you give a function that validates an expense without changing it?

  • fn check(expense: Expense)
  • fn check(expense: &Expense)
  • fn check(expense: &mut Expense)
  • fn check(expense: Arc<Expense>)
Read-only access is a shared borrow. Taking it by value would consume the caller's expense.

(Control flow) Inside a function returning Result, a ? fails after a transaction was opened. What is guaranteed?

  • The changes so far are committed automatically
  • The transaction is dropped and rolled back
  • The program panics because the transaction leaked
  • Nothing; you must call rollback inside a catch
Early return drops the owner, and drop rolls back. (34, 36)

(Data types) Why do Ledgerly's accessors return &Merchant but Money (no &)?

  • Merchant is private, Money is a public type
  • Money is Copy and cheap; Merchant owns text
  • References can only point to tuple struct values
  • Money is always stored on the heap anyway
Copy types are returned by value. Owning types are lent out to avoid a clone. (20, 38)

Annotate a real function

Do this in VS Code (15 minutes)

Open . For every variable and argument in execute, write next to it (as a comment you won't commit) one of: owned, moved here, & borrowed, &mut borrowed, Copy, or Arc clone.

Spot-check answers

&self: shared borrow, so many requests run at once. action, team, id, caller: Copy. reason: Option<&str>: a borrowed string inside an option.

transaction: owned here, lent as &mut four times, consumed by commit() (which takes self). found.value: moved into expense. &expense: shared borrow for the update. expense: finally moved into the returned Versioned.

self.memberships.as_ref(): borrows the trait object inside the Arc as &dyn MembershipLookup.
