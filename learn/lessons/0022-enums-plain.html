Enums I: plain variants

Where TypeScript writes type Category = "TRAVEL" | "MEALS" | …, Rust writes an enum. The values are not strings, and converting to and from text is explicit.

By the end of this lesson

You can read Category, ExpenseStatus, Action and Role: how they're declared, how a variant is named (Category::Travel), and how they become the strings the API and database use.

Union of literals vs enum

  • A variant is named through its enum, Category::Travel. Inside impl Category you can write Self::Travel.
  • The value is a tiny tag (one byte here), not text. Category::Travel and "TRAVEL" are unrelated until code connects them.
  • derive adds abilities: PartialEq enables ==, Copy lets it be copied like a number, Hash lets it be a map key, Debug prints Travel with {:?}.

Text in, text out

Every plain enum in Ledgerly follows this pattern:

  1. ALL: an array of every variant, for loops and for parsing (TS would use an as const array).
  2. as_str: a match that maps each variant to its wire name. You met match in lesson 9, and lesson 31 covers it fully. The key fact: if a variant is missing, it doesn't compile.
  3. Display (for {} in format!) and FromStr (for "TRAVEL".parse::<Category>()), the reverse direction, which can fail with UnknownCategory. Lesson 51 shows these.
In Ledgerly: an enum with no ordering, on purpose

Comparing with < needs the trait Ord, and Role doesn't derive it. So role >= Role::Approver doesn't compile; you must write role.includes(Role::Approver). What a type can't do is part of its design.

Where the comparison breaks

A TS union of strings is its wire format, so JSON.parse gives you a "Category" for free (unchecked). A Rust enum is a separate type: text becomes a Category only through code that can reject bad input (FromStr or serde, lesson 68). TS's own enum keyword is closer in syntax, but Rust enums can do far more, as the next lesson shows.

Check yourself

How do you refer to the "meals" category in code outside impl Category?

  • "MEALS"
  • Meals
  • Category::Meals
  • Category.MEALS
Variants live in the enum's namespace, written with ::. Only with use Category::*; (rare) could you write Meals alone.

Why doesn't role >= Role::Approver compile?

  • Enums can never be compared with any operator
  • Role doesn't implement Ord, which ordering needs
  • The variants have no numbers assigned to them
  • Only integers support comparison operators in Rust
Operators come from traits: == from PartialEq, < from PartialOrd. Ledgerly leaves ordering out deliberately.

You add Training to Category. What happens to as_str?

  • It returns an empty string for the new variant
  • It panics at runtime when called with Training
  • It stops compiling until Training gets an arm
  • It returns "TRAINING", derived from the variant name
match must cover every variant. The compiler lists the missing one (E0004).
