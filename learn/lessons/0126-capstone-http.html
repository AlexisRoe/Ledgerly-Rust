Decisions to make

  • State: Arc<dyn LinkStore>, an mpsc::Sender<Slug> for visits, and an Arc<AtomicU64> counter for generated slugs. Everything in state is cloned per request, so keep it cheap.
  • One error enum, one IntoResponse: handlers return Result<_, ApiError> and use ?; the status mapping lives in one exhaustive match.
  • An invalid slug in a GET is a 404, not a 400: from the client's view, that link just doesn't exist.
  • Redirects never wait for the counter: try_send, not send().await. A full queue loses a count, not latency.
Reference solution

Three ?s with three different error types, each converted by #[from]. loop is an expression: break link is its value. The exhaustive match on StoreError means a new store error would have to be handled here.

Where the comparison breaks

In Express, an error thrown in a handler reaches an error middleware with whatever type it has, and you map it there with instanceof. In axum, the handler's return type says which errors exist, and the compiler checks the mapping is complete. Ledgerly does exactly this, at scale (lesson 58).

Check yourself

Why try_send for visits instead of send().await?

  • Because send().await isn't allowed in axum handlers
  • A full queue must never slow the redirect
  • Because try_send guarantees that no visit is lost
  • Because try_send is the only cancel-safe sending method
A trade-off made on purpose, and logged when it happens.

How do the tests call the router without opening a port?

  • By starting a server on a random port
  • oneshot drives the Router as a tower Service
  • By calling each handler function directly instead
  • By mocking axum with a fake router type
A Router is a tower Service; ServiceExt::oneshot drives it once.
