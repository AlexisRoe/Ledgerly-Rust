Data types

impl blocks: methods and associated functions

Rust has no class. Data lives in a struct, behaviour in a separate impl block, and the first parameter says how a method may touch the data.

By the end of this lesson

You can read any method signature in Expense and say whether it only reads (&self), modifies (&mut self), or consumes (self) the value, and tell a method from a static constructor.

Class vs struct + impl

  • Associated function (no self parameter) = static method. Call it on the type: Merchant::new("…").
  • Method (first parameter is some form of self) = instance method. Call it on a value: merchant.as_str().
  • Self (capital S) is the type being implemented. self is the value, Rust's this, but written out as a parameter.
  • new is a convention, not a keyword. There are no constructors: a function that returns Self (or Result<Self, _> when it validates) does the job. Ledgerly also has Expense::draft, Expense::restore and Money::parse, each named for what it does.

In Ledgerly: a transition

The signature alone tells you that approve may change the expense (&mut self) and may fail (Result). The caller must hold a mutable binding: let mut e = …; e.approve(actor)?;. Because ? returns early, a refused approval never reaches the assignment, so it changes nothing.

A type can have many impl blocks, also in different files of the same crate, and impl Trait for Type blocks for interfaces (). Methods on a field-less value still take self: Role::includes(self, other: Self) takes self by value because a Role is a tiny copyable value ().

Where the comparison breaks

No inheritance, no extends, no super(). Shared behaviour comes from traits and composition. And &self vs &mut self is enforced: inside an &self method, self.status = … doesn't compile. TS's readonly is only per field, and a method can mutate anything it likes.

Check yourself

How do you call pub fn new(text: &str) -> Result<Self, InvalidInput> defined in impl Merchant?

  • new Merchant("Bahn")
  • merchant.new("Bahn")
  • Merchant::new("Bahn")
  • Merchant.new("Bahn")
No self parameter means an associated function, called with Type::name. It returns a Result, so the caller still has to handle the error.

Which signature lets a method change the expense's status?

  • fn reopen(&self, actor: Actor)
  • fn reopen(&mut self, actor: Actor)
  • fn reopen(actor: Actor)
  • fn reopen(Self, actor: Actor)
Writing to self.status needs mutable access, which is &mut self.

What's the difference between Self and self?

  • None at all; Rust identifiers are case insensitive
  • Self is the type, self is the value
  • Self is static, self is the parent module
  • Self is for traits, self is for structs
Inside impl Merchant, Self is Merchant and self is the instance the method was called on.
