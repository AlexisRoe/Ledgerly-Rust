Name three integer types Ledgerly uses and why each.
u32 for counts/page sizes (can't be negative), u64 for byte sizes, usize for lengths/indexes, i64 to match Postgres bigint, u8 for a currency's decimals. (16)
When does a function take &str and when does it return String?
Take &str when it only reads. Return String when it creates new text, and &str when it returns part of its input. (18)
The three shapes of an enum variant?
Unit (Deleted), tuple-like (RuleViolated(&'static str)), struct-like (SelfDealing { action }). (23)
What's the difference between &self, &mut self and self?
Read-only borrow, mutable borrow, take ownership (consume). (21)

Mixed questions

Which type would Ledgerly use for "optional filter by currency code"?

  • String
  • &str | null
  • Option<String>
  • Result<String, ()>
Criteria::currency is exactly Option<String>. Absence is not an error. (24)

What's the Rust equivalent of a TS discriminated union?

  • A struct with an optional kind field
  • An enum whose variants carry their own data
  • A trait with one implementation per variant
  • A tuple whose first element names the variant
Enum variants with fields. match narrows them, and the compiler checks exhaustiveness. (23)

Why does Expense::rejections() return a slice?

  • Vectors can never be returned from any methods
  • Callers can read but never push or copy
  • Slices are always sorted by their insertion order
  • Slices are stored on the stack, vectors not
&[Rejection] borrows without copying and has no mutating methods. (19)

What prevents code outside money from building an invalid Money?

  • A runtime check in every function using Money
  • Private fields: only validating constructors can build it
  • A clippy lint that forbids struct literal syntax
  • The database rejects invalid amounts on insert
Field privacy plus constructors that return Result: parse, don't validate. (13, 26)

Read Result<(Merchant, Option<Note>), InvalidInput>.

  • A merchant, or a note, or an invalid input
  • May fail; if not, a merchant and maybe a note
  • A list of merchants, each with an optional note
  • An invalid input that contains a merchant and note
Outside in: a Result of a tuple (two values) whose second part is optional. (19, 25, 27)

Explain the aggregate

Do this in VS Code (10 minutes)

Open . For each of the ten fields of Expense, write one line: what its type is, what TS type you'd have used, and what the Rust type guarantees that the TS one wouldn't.

Model answers for four of them

id: ExpenseId: TS string. Can't be confused with a TeamId; always a UUIDv7.

money: Money: TS { amount: number; currency: string }. Always positive, correct decimals for its currency, fits the column; no float rounding.

note: Option<Note>: TS note?: string. Absence is explicit, and a present note is within the length limit.

rejections: Vec<Rejection>: TS Rejection[]. Private, so only reject can push, and outsiders get a read-only slice.
