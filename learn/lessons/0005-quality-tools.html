rustfmt: one style, almost no options

Like Prettier, rustfmt has opinions and few knobs. Ledgerly only widens lines to 120 characters. Every Rust project looks the same, which makes reading other people's crates easier. cargo fmt --all --check is the CI form: it fails instead of rewriting files.

clippy: 700+ lints, in levels

The compiler (rustc) already warns about unused variables and similar problems. Clippy adds hundreds of lints on top: correctness, style, performance, and "restriction" lints that a project opts into (lint list). Every lint has a level (rustc: lint levels):

LevelESLintEffect
allow"off"Silent
warn"warn"Warning (Ledgerly's CI turns warnings into errors with -D warnings)
deny"error"Error; can still be overridden lower down, with a reason
forbid(none)Error that nothing below may override

So .unwrap() is banned in production code but fine in tests: a panicking test is just a failing test.

rust-analyzer: let the compiler talk while you read

Install the rust-analyzer extension in VS Code (not the old "Rust" extension). For this course, three features matter most:

  • Inlay hints show inferred types in grey after let bindings and parameter names at call sites, as if the code had full annotations. They're the best reading aid there is.
  • Hover shows a type's docs, and Go to Definition (F12) works into dependencies and the standard library.
  • Errors inline: it runs cargo check on save.

cargo-deny: what may enter the dependency tree

Four checks: advisories (known vulnerabilities from the RustSec database, like npm audit), licenses, bans (forbidden or duplicate crates) and sources (only crates.io, no random git URLs) (cargo-deny book).

nextest: the test runner

cargo test is built in. cargo-nextest runs each test in its own process, in parallel, with timeouts. Ledgerly's integration tests start servers, so a hanging test must be killed (see .config/nextest.toml). Nextest doesn't run doc tests, so just test also runs cargo test --doc.

Where the comparison breaks

In TypeScript, the linter and the type checker are separate worlds, and ESLint can't see types without extra setup. Clippy is the compiler with more checks: it has full type information for every lint. And because rustfmt is the official formatter, there's no Prettier-vs-StandardJS debate to have.

Try it
  1. In VS Code, install rust-analyzer, open crates/app/src/main.rs and wait for indexing to finish. Look at the grey type hints after let config and let runtime.
  2. Hover over ExitCode, then F12 into it. You're now reading the standard library.
  3. In a terminal: cargo clippy -p ledgerly-shared (should finish without warnings) and cargo fmt --all --check.

Check yourself

Which tool would complain about a GPL-licensed dependency?

  • rustfmt
  • clippy
  • cargo-deny
  • nextest
deny.toml's [licenses] allow list contains only permissive licences, so cargo deny check fails on anything else.

What's the difference between deny and forbid?

  • Deny errors in CI only, forbid errors everywhere
  • Forbid can't be overridden lower down; deny can
  • Forbid applies to clippy, deny to the compiler
  • There is none; they're aliases of each other
A deny can be relaxed on one item with #[allow(...)] or #[expect(...)]. A forbid can't. That's why unsafe_code is forbid.

Why may tests call .unwrap() in Ledgerly?

  • Tests are compiled without any clippy lints
  • clippy.toml allows it in test code
  • Each test file has an allow attribute
  • unwrap never panics inside a test function
allow-unwrap-in-tests = true in clippy.toml. A panic in a test just fails that test, which is what you want.
