if let: one case, maybe an else

"If initialising logging failed, stop the program." The Ok case needs no code, so a full match would only add noise. if let works with any pattern: Some(x), Err(e), Action::Reject, a tuple… (Book 6.3).

let … else: the guard clause for patterns

From the login use case: if there's no user, or the password didn't match, count a failed attempt (for rate limiting) and answer 401. Otherwise user is bound for the rest of the function, with no extra nesting. The else block must leave: return, break, continue or a panic. That's the "happy path on the left" style you'd write in TS with early returns (Rust by Example: let-else).

while let: loop until the pattern fails

At startup: keep trying to create the receipts bucket every two seconds while it fails, warning only once.

matches!: a pattern test as a bool

Where the comparison breaks

TS narrows by control flow: after if (!user) return;, the compiler knows user is defined. Rust doesn't narrow an existing variable. You bind a new one through a pattern (let Some(user) = … else), and the shadowing is often deliberate, as with user above, an Option<User> that becomes a User.

After let Some(user) = maybe else { return Err(E) };, what's the type of user?

  • Option<User>
  • User
  • Result<User, E>
  • bool
The pattern unwraps Some. If it didn't match, the else returned, so afterwards user is a plain User.

What must the else block of a let … else do?

  • Provide a default value for the binding
  • Leave the scope: return, break, continue or panic
  • Log the failure and then continue normally
  • Nothing; an empty else block is perfectly fine
Its type is ! ("never returns"). Otherwise the binding would be undefined afterwards. For a default, use unwrap_or.

Which is the idiomatic Rust for TS const isFinal = s === "APPROVED" || s === "REIMBURSED";?

  • let is_final = s in [Approved, Reimbursed];
  • let is_final = matches!(s, Approved | Reimbursed);
  • let is_final = if let Approved | Reimbursed = s;
  • let is_final = s.is(Approved | Reimbursed);
matches! turns a pattern into a bool (with ExpenseStatus:: prefixes in real code).
