Error handling the Ledgerly way

Custom errors with thiserror

An error type is just an enum. The thiserror crate's derive writes the boring parts: the message (Display), the standard Error trait, and the From conversions.

By the end of this lesson

You can read every attribute on Ledgerly's error enums (#[error("…")] with placeholders, #[error(transparent)], #[from]) and write a small error enum yourself.

The TS class vs the Rust enum

The attributes

AttributeGenerates
#[derive(thiserror::Error)]impl std::error::Error (the standard "this is an error" trait) and Display
#[error("Amount must be positive: {amount}")]the message; {amount} refers to a field
#[error("{0}")]positional field of a tuple variant
#[error(transparent)]"use the inner error's message unchanged"
#[from] on a fieldimpl From<Inner> for ThisError, so ? converts automatically

(thiserror docs.) So MoneyError::Currency(…) prints the JDK-compatible currency message from CurrencyError, and inside Money::parse, Currency::from_code(code)? turns a CurrencyError into a MoneyError automatically. That's the conversion lesson 34 promised.

In Ledgerly: messages are part of the contract

Ledgerly must answer with exactly Ledgerly-Java's error messages, so the strings in #[error(…)] are copied from Java and tested. When an error's message contains a value ({amount}), it uses that value's Display, which is why ExpenseStatus and Action implement Display with Java's names: "Expense is DRAFT and cannot APPROVE".

Errors that might be logged never put a secret or personal value in their message: PersistenceError::Corrupt names the column, never its content.

Where the comparison breaks

TS error hierarchies use subclasses and instanceof. A caller can't know which subclasses exist, and a catch gets unknown. A Rust error enum lists every possible failure in one place, and a match over it is checked for completeness. thiserror is for libraries and layers that callers match on. Its sibling anyhow (one opaque error type for applications) isn't used in Ledgerly, because every error must map to a precise HTTP answer.

Check yourself

What does Currency(#[from] CurrencyError) generate?

  • A function that parses a currency from a string
  • A From impl, so ? converts a CurrencyError
  • A Display impl that prints the currency code
  • A match arm that handles currency errors itself
impl From<CurrencyError> for MoneyError, wrapping it in the Currency variant.

What does #[error(transparent)] do?

  • Hides the error message from the API's response
  • Shows the wrapped inner error's message exactly as-is
  • Makes the variant invisible to all match expressions
  • Logs the error without returning it to callers
Used for variants that just wrap another error, like ExpenseError::InvalidInput.

In #[error("Expense is {from} and cannot {action}")], what prints {from}?

  • The Debug output of the from field, like Draft
  • The Display output of the from field, DRAFT
  • The variable called from in the calling function
  • The name of the function that created the error
Placeholders name fields of the variant and use Display, which Ledgerly implements with Java's upper-case names.
