Where to go next

You set out to read Ledgerly, understand it, and make small changes. Here's how to check that you can, how to make it stick, and where to go from here.

Practice beyond Ledgerly

  • Rustlings: ~100 small exercises with failing tests, the same format as learn/playground. Ideal for 15-minute sessions.
  • Comprehensive Rust: Google's course, good for a second explanation of anything that didn't click.
  • The Book: chapters this course only touched: 12 (a CLI project), 15 (smart pointers in depth), 16 (threads), 19 (patterns), 20 (advanced features).
  • Tokio tutorial: builds a mini Redis, the best way to get fluent with async.

Ask people

  • Rust Users Forum: the official forum, beginner-friendly. Post a minimal snippet and the full compiler error.
  • r/learnrust: quick questions.
  • This Week in Rust: a weekly digest, once reading Rust feels normal.

Next changes in Ledgerly

When you're ready for real work, the natural next step is a change that starts in Ledgerly-Java (contract or schema) and then gets ported: a new optional field on an expense, say. It touches every layer you've learned: api/openapi.yaml and the migration (from Java), dto.rs (serde), the domain (a newtype?), persistence (sqlx + just sqlx-prepare), tests at each layer, and a parity test. Ask the agent to pair with you on it step by step, with you typing.

Check yourself, one last time

A friend asks why Rust needs both String and &str. Your answer?

  • Historical reasons only; today the two are interchangeable
  • One owns its text; the other borrows a view
  • One holds ASCII text; the other holds UTF-8
  • One lives on the stack; the other is static
Ownership vs borrowing, the idea the whole course comes back to.

You add a variant to an error enum. What's the first thing you expect?

  • A runtime 500 the first time it happens
  • Compile errors where matches must map it now
  • Nothing until the parity suite runs against Java
  • A clippy warning suggesting a wildcard pattern instead
Exhaustive matches without _: the compiler lists every decision to make.
