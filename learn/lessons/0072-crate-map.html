Reading Ledgerly end to end

The crate map

Nine crates, one binary. Before following a request through them, learn what each crate owns and which may depend on which. The compiler enforces those arrows.

By the end of this lesson

Given a feature ("refresh tokens", "receipt virus scan", "audit trail"), you can name the crate it lives in and the crates it's allowed to use, and explain how expenses asks receipts a question without depending on it.

Warm-up
What does cargo do with a dependency cycle between crates?
Refuses it, so module boundaries become compile errors. (4)
How does a trait object help two crates talk without a dependency?
One crate defines the trait, the other implements it, and the app wires them together. (53)

The arrows

"receipts → expenses" means receipts may use expenses' public API, never the other way round. So how does submitting an expense check its receipts? The dependency inversion you saw in lesson 53: expenses owns trait ReceiptChecks, receipts implements it, and app passes Receipts::checks() into ledgerly_expenses::routes(…). The arrows stay one-way.

In Ledgerly: the arrows are tested

Cargo already forbids cycles. This test also catches an arrow that isn't a cycle but isn't allowed (say, receipts → identity) by reading cargo metadata. The same file checks that only "adapter" modules (persistence, scanners, storage) open network connections. That's Ledgerly's SSRF protection (OWASP API7).

Where the comparison breaks

In a TS monorepo, nothing stops expenses from importing a file deep inside receipts, or two packages from importing each other. Ledgerly gets three levels of enforcement: cargo (no cycles), visibility (pub(crate) internals), and the architecture test (exact arrows). Rule 2 from CONCEPT §3 adds a convention on top: a module never touches another module's tables.

Check yourself

Where would you look for the refresh-token rotation logic?

  • crates/shared
  • crates/identity
  • crates/teams
  • crates/app
Users, passwords and tokens are identity's. (The use case is identity/src/application/refresh.rs.)

May teams call a function of expenses?

  • Yes, every crate may use every other crate
  • No, the arrow points from expenses to teams
  • Yes, but only through the expenses facade
  • Only inside tests marked with cfg test
expenses → teams exists, so teams → expenses would be a cycle that cargo refuses.

How does the audit trail learn that an expense was approved?

  • It queries the expenses table every few seconds
  • It listens to the events that expenses publishes
  • expenses calls an audit function after each change
  • app copies rows between the tables at shutdown
audit depends only on events. Expenses writes an event in its transaction, and the outbox delivers it to audit's listener after commit.
