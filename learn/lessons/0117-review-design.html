Mixed questions

A TeamName must be 1–100 characters. A handler deserialises it from JSON. Where is the check?

  • In the handler, right after deserialising the body
  • In TeamName's constructor, which serde's try_from calls
  • In the database, through a CHECK constraint only
  • In every function that receives a team name
One door; serde uses it too. (112)

(Traits) A public library type should implement Debug even if you don't need it. Why?

  • Because the compiler requires Debug on public types
  • Users can't add it later: the orphan rule
  • Because Debug makes the type faster to clone
  • Because Display is generated from Debug for free
Foreign trait, foreign type: only you can write the impl. (91, 114)

(Async) A builder's build() opens a database connection. What signature?

  • fn build(self) -> Pool
  • async fn build(self) -> Result<Pool, BuildError>
  • fn build(&self) -> Option<Pool>
  • fn build(self) -> impl Future<Output = Pool>
It does I/O (async) and can fail (Result, with a reason). (25, 62, 113)

You want test-only helpers that other crates' tests can use. What does Ledgerly do?

  • Copies the helpers into each crate's own tests
  • A testing feature, enabled only in dev-dependencies
  • Marks the helpers pub and lets them ship
  • Puts the helpers in a separate git repository
#[cfg(any(test, feature = "testing"))], never in the binary. (115)

Design sketch: expense tags

Types first, no logic

Imagine expenses can carry up to 5 tags, each 1–30 characters, lowercase, unique per expense. Sketch only signatures:

  1. A Tag type: field, constructor, accessor, derives.
  2. A Tags collection type that enforces "at most 5, unique". What does it offer instead of Vec's methods?
  3. The error type(s): who will match on them, and what does the web layer need from them?
  4. Where does serde parse them, and how?
One possible answer
#[derive(Debug, Clone, PartialEq, Eq, Hash)] pub struct Tag(String); with Tag::new(&str) -> Result<Tag, InvalidInput> (trims, lowercases, checks length) and as_str(). pub struct Tags(Vec<Tag>); with Tags::new(Vec<Tag>) -> Result<Tags, InvalidInput>, iter(), len(), contains(&Tag); no push, or a try_add returning Result. Errors reuse Ledgerly's InvalidInput { field: "tags", message }, because the web layer turns it into a 400 with a field name. JSON: #[serde(try_from = "Vec<String>")] on Tags.
