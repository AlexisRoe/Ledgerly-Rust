When does a closure need move?

Mixed questions

Which chain returns the names of approved expenses?

  • xs.map(|e| e.name).filter(|e| e.approved)
  • xs.iter().filter(|e| e.approved).map(|e| e.name.clone()).collect::<Vec<_>>()
  • xs.iter().filter(|e| e.approved).map(|e| e.name.clone())
  • xs.filter_map(|e| e.approved).collect()
You need a start (iter), filter before map, and a consumer. Option 3 is lazy and produces nothing on its own.

(Ownership) let names: Vec<&str> = expenses.iter().map(|e| e.merchant.as_str()).collect(); What happens if you then drop(expenses) and use names?

  • Fine; names copied the text out
  • Compile error: names still borrows from expenses
  • A runtime panic when names is accessed
  • Fine; the strings move into names
&str items borrow from the expenses (E0505). Collect Strings (.to_owned()) if you need them to outlive the source.

What's the difference between .ok_or(err()) and .ok_or_else(err)?

  • ok_or_else converts the error type, ok_or doesn't
  • ok_or always builds it; ok_or_else lazily
  • ok_or returns Option, ok_or_else returns a Result
  • None; they're aliases kept for compatibility reasons
Arguments are evaluated before the call. Passing a closure delays the work.

(Control flow) What does note.map(Note::new).transpose()? do when note is None?

  • Returns an error because it's missing
  • Continues with None; nothing gets validated here
  • Panics, since transpose needs a Some value
  • Creates an empty Note, continuing with Some
None → Ok(None) → ? passes None through.
