What this shows

The compile error in step 1 is a feature: Rust tests can't call a method that doesn't exist, so "red" starts at compile time. And the test checks a relationship (is_final agrees with target_from) rather than a list of examples. That's the property-testing mindset from lesson 66, applied with a plain for loop over ALL.

Check yourself

Why derive stuck from target_from instead of hard-coding Reimbursed in the test?

  • Hard-coded values aren't allowed inside Rust tests
  • The test stays right if the workflow changes
  • target_from is faster than writing out a list
  • The compiler can't compare enum values in tests
The test encodes the definition ("no action leads anywhere"), not today's answer.

Why const fn?

  • Only const functions may return a bool value
  • It can also be used in constants, like as_str
  • const makes the function private to its module
  • clippy requires every match function to be const
It's consistent with the other ExpenseStatus methods and costs nothing; a match on a Copy enum is allowed in const fn.
