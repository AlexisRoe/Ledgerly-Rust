Required method vs default method?
A required method has only a signature, and each implementor writes it. A default method has a body in the trait. (49)
Which trait makes .parse::<X>() work, and which makes .to_string() work?
FromStr, and Display. (51)
Generics vs dyn in one sentence each.
Generics: the type is fixed at compile time, one copy per type, fast. dyn: one copy, chosen at runtime, behind a pointer. (52, 53)

Mixed questions

What makes assert_eq!(a, b) compile for two Expense values?

  • All structs support equality checks by default
  • Expense derives PartialEq and Debug, both needed
  • assert_eq compares the two memory addresses instead
  • Expense implements Display, which is used for comparing
== comes from PartialEq; the failure message needs Debug. (50)

Code in expenses needs the number of receipts but can't depend on the receipts crate. What's Ledgerly's solution?

  • Copy the receipts code into the expenses crate
  • expenses defines a trait, and receipts implements it
  • Query the receipts table directly with raw SQL
  • Make both crates depend on each other
ReceiptChecks lives in expenses and is passed in as Arc<dyn ReceiptChecks>. The dependency points the allowed way. (53)

Which bound lets a generic function print its argument with {}?

  • T: Debug
  • T: Display
  • T: ToString + Clone
  • T: Into<String>
{} needs Display; {:?} needs Debug. (50, 52)

(Ownership) A use case stores clock: Arc<dyn Clock>. Eight use cases share one clock. How many clocks exist?

  • Eight, because every Arc clone copies the clock
  • One; the eight Arcs point to the same clock
  • Nine: the original plus one copy per use case
  • None until the first use case calls clock.now()
Cloning an Arc adds an owner, not a clock. (42)

(Data types) Why does Role not derive Ord?

  • Enums can't derive Ord in the 2024 edition
  • So rank checks go through includes, not comparisons
  • Roles are stored as text, which can't sort
  • Ord would make Role larger than one byte
A missing trait is a design rule: role >= Approver can't be written, and role.includes(Approver) is the only way. (22, 50)
