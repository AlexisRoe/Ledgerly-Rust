Data types

Tuples, arrays, slices and Vec

TypeScript's T[] splits into three Rust types: a fixed-size array, a growable Vec, and a borrowed view called a slice.

By the end of this lesson

You can read [Self; 6], Vec<Rejection>, &[Rejection] and (Merchant, Option<Note>) in Ledgerly, and pick the right one in your own code.

Warm-up
What's the difference between String and &str?
String owns its text, while &str is a borrowed view into text someone else owns.
Why does text.len() differ from JS's text.length?
Rust counts UTF-8 bytes, JS counts UTF-16 units.

In Ledgerly: all four

An array: exactly three, fixed at compile time. Change the 3 and it won't compile.

The Expense owns a Vec it can push to. Callers get a &[Rejection]: they can read and iterate, but a slice has no push. Java needed Collections.unmodifiableList and a test for that, and here the type says it.

A tuple as a return type: two values without defining a struct. The caller destructures it: let (merchant, note) = new.checked(clock)?;

Everyday operations

Note the two kinds of indexing: v[i] panics when out of bounds, and v.get(i) returns an Option. Ledgerly's domain modules deny clippy::indexing_slicing, so only the get style is allowed there.

Where the comparison breaks
  • JS arrays can hold anything and have holes. A Vec<T> holds only Ts, contiguous in memory.
  • ids[99] in JS is undefined. In Rust it's a panic, which crashes the request (or the program). Prefer .get(), .first() and iterators.
  • A function taking &[T] accepts a &Vec<T>, an array or part of either, so take slices as parameters, as you take &str.

Check yourself

Why does Expense::rejections() return &[Rejection] instead of &Vec<Rejection> or Vec<Rejection>?

  • Slices are faster to iterate than vectors
  • Callers can read without copying or pushing
  • A Vec can't be returned from a method
  • Slices are sorted, vectors are not sorted
A slice borrows (no copy) and offers no mutating methods. Returning Vec<Rejection> would mean cloning every rejection.

What happens on let v: Vec<u32> = Vec::new(); v[0]?

  • Returns undefined, just like JavaScript arrays do
  • Returns zero, the default for u32 values
  • Panics: index out of bounds at runtime
  • Fails to compile: index is never valid
Indexing checks bounds at runtime and panics. v.get(0) would return None.

Which type is Role::ALL?

  • Vec<Role>
  • &[Role]
  • [Role; 3]
  • (Role, Role, Role)
An array: fixed length 3, every element a Role, usable in a const. (Inside impl Role, Self means Role.)
