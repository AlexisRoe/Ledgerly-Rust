Ownership and borrowing

Move semantics

In JavaScript, b = a copies a reference and both names see the same object. In Rust, let b = a; moves the value: b owns it now, and a is no longer usable.

By the end of this lesson

You can predict "use of moved value" errors: after an assignment, after passing to a function, after a for loop, and after a method that takes self.

Warm-up
The three ownership rules?
One owner per value; one owner at a time; dropped when the owner leaves scope. (36)
Why does a transaction roll back when ? returns early?

Four ways to move a value

A move doesn't copy the heap data. It copies the small handle (pointer, length, capacity) and marks the old name as dead, so the data still has exactly one owner and is freed exactly once (Book 4.1, "Move").

In Ledgerly: moves you can now see
  • let mut expense = found.value; moves the Expense out of the found struct. After this, found.value is unusable, but found.version (a separate field) is still fine. That's a partial move.
  • value: expense moves it into the returned Versioned. The caller becomes the new owner. No copy of the expense ever happened.

teams is moved into the wrapper, and routes() takes self, so the ExpensesApi is consumed and turned into a route table. Nothing can use the API object afterwards, and nothing needs to.

Reading the error

Three labels tell the whole story: where the value was created, where it moved, and where you used it afterwards. The fix is one of: use b instead, borrow instead of moving (&a, lesson 39), or clone if you truly need two copies (next lesson).

Where the comparison breaks

JS never invalidates a variable. Here, the same-looking line let b = a; makes a unusable for a Vec but not for a u32. The difference is the Copy trait, which the error message mentions and which comes in the next lesson.

After for item in items { … } with items: Vec<Item>, can you use items?

  • Yes, a for loop never changes the collection
  • No, it was consumed; loop over &items instead
  • Yes, but only while the vector is non-empty
  • No, but calling items.reset() will restore the vector
for x in v takes ownership. for x in &v borrows.

What does a move of a Vec with a million elements cost?

  • Copying all one million elements to a new place
  • Copying a small handle; the elements stay put
  • Nothing at all, not even copying the handle
  • A heap allocation plus a later garbage collection
A Vec is a pointer, a length and a capacity. A move copies those three words and invalidates the source.
