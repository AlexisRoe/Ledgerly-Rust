Result: errors as values

No throw, no try/catch. A function that can fail says so in its return type, and the caller can't ignore it.

By the end of this lesson

You can read Result<T, E> signatures in Ledgerly, including Result<(), E> and Result<Option<T>, E>, handle one with match, and recognise ? as "return the error to my caller".

What does .ok_or(E) turn an Option into?
A Result: Some(v) → Ok(v), None → Err(E).

Another enum

  • The signature tells the truth: -> Result<Self, MoneyError> can fail, and only with a MoneyError. Ledgerly's doc comments add a # Errors section listing which variants, in which order.
  • You can't use the Money without getting past the Err case. Ignoring a Result entirely is a compiler warning (unused Result that must be used).
  • ? after a Result: if it's Ok(v), take v; if it's Err(e), return Err(e) from the current function immediately, converting the error type if needed. It's the "rethrow" that you write explicitly. Lesson 34 and section 8 go deeper.

Shapes you'll see constantly

SignatureMeansTS feel
Result<Money, MoneyError>a value, or a typed errorMoney that may throw
Result<(), ExpenseError>"it worked", or why notvoid that may throw
Result<Option<Expense>, PersistenceError>the query failed, or it worked and found one or nonePromise<Expense | undefined> that may reject
In Ledgerly: "not found" is not an error

The outer Result says the database call can fail. The inner Option says a successful query may find nothing. The application layer then decides that None means HTTP 404 (the access::load chain in the last lesson).

Where the comparison breaks

Libraries like neverthrow or Effect bring Result to TS, but they compete with throw, so anything can still blow up. In Rust, Result is the way to fail. Panics exist, but they're for bugs, not for expected failures like bad input (). Also, catch (e) gives you unknown, while Err(e) gives you exactly the declared error type, usually an enum you can match on.

Check yourself

What does Result<(), ExpenseError> as the return type of approve mean?

  • It always fails and returns an ExpenseError value
  • Success carries no value; failure carries the reason
  • It returns either nothing or an expense value
  • The error type stays unknown at compile time
() is "nothing". The interesting information is whether it worked, and if not, which ExpenseError.

In let currency = Currency::from_code(code)?;, what happens when the code is invalid?

  • currency is set to None and execution continues
  • The program panics with the currency error text
  • The enclosing function returns that error right away
  • The error is logged; a default currency follows
? returns early with the Err. In Money::parse, a CurrencyError is converted into a MoneyError on the way out (section 8 shows how).

A query returns Ok(None). What does that mean?

  • The database call failed with an unknown error
  • The query worked but matched no row at all
  • The row exists but has only empty columns
  • The connection was closed before it could answer
The Result is about the call, the Option about the data. Failure would be Err(PersistenceError::Database(…)).
