Functions, closures and iterators

Iterators vs array methods

.map(), .filter(), .find(), .some() all exist in Rust, but on iterators, not on Vec. They're lazy, so nothing happens until something consumes them, usually .collect().

By the end of this lesson

You can read iterator chains such as Self::ALL.into_iter().find(…).ok_or_else(…) and problems.iter().enumerate().filter_map(…).collect(), and translate TS array code into them.

Start, transform, finish

Every chain has three parts (Book 13.2):

  1. Start: .iter() (yields &T, borrows), .iter_mut() (&mut T), .into_iter() (yields T, consumes the collection; for Copy arrays like ALL, it just copies).
  2. Adapters, which are lazy and return a new iterator: map, filter, filter_map, enumerate, zip, take, skip, copied, chain…
  3. Consumer, which runs everything: collect, find, any, all, count, sum, fold, for loops.

collect() can build many collection types, so it usually needs a type hint: let v: Vec<_> = … .collect(); or .collect::<Vec<_>>(). A function can be passed instead of a closure: .any(Option::is_some), .map(ExpenseResponse::from).

Where the comparison breaks

TS array methods are eager: each .map builds a whole new array. Rust iterators are lazy and fused: a map + filter + collect chain runs as one loop with no intermediate collections, compiled to roughly the code you'd write by hand. Forget the consumer and nothing runs at all (the compiler warns "iterators are lazy and do nothing unless consumed").

Check yourself

What does roles.iter().map(|r| r.as_str()); do on its own?

  • Builds a vector of names, then discards it
  • Nothing at all; the lazy iterator is never consumed
  • Prints each role name to the terminal output
  • Changes each role in place into its name
Adapters are lazy. Without collect, for or another consumer, no closure is called, and the compiler warns.

Which is TS's array.some(fn)?

  • .all(fn)
  • .any(fn)
  • .find(fn)
  • .filter(fn)
any ↔ some, all ↔ every. Both stop early.

What does filter_map do?

  • Filters first, and then maps the remaining items
  • Maps to Option, keeping only the Some values
  • Maps every item, then sorts the result list
  • Filters items whose map lookup returns a value
The closure returns Option<U>. Some(u) is kept as u, and None is dropped.
