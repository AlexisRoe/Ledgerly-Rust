Testing

Integration, doc and property tests

Three more kinds of test, all run by cargo test: tests that use only the public API, examples in docs that must compile, and tests that try hundreds of random inputs.

By the end of this lesson

You can tell the three kinds apart by where they live, read a proptest! block, and know which Ledgerly tests need a database.

In Ledgerly: an integration test against real Postgres

TestDatabase (from ledgerly_shared's testing feature) starts or reuses a Postgres container with Ledgerly-Java's schema and gives each test its own database. That's why just test needs Docker. These files start with #![allow(clippy::unwrap_used, …)] because clippy.toml's exemption covers only #[test] functions, not the helpers around them.

In Ledgerly: properties of Money

Instead of three hand-picked amounts, original in any_money() generates hundreds of random valid Money values (any currency, any allowed amount) and checks that a rule holds for all of them: "print, then parse, gives back the same value". When one fails, proptest shrinks it to the smallest failing input (proptest book).

Doc tests, once more

cargo test --doc compiles every ``` example in the docs as a little program that uses the crate from outside. Ledgerly uses one to prove that swapping a TeamId and an ExpenseId doesn't compile (lesson 10). Nextest doesn't run doc tests, which is why just test runs both.

Where the comparison breaks

In TS the distinction between unit and integration tests is a folder convention. In Rust it's enforced: a file in tests/ is a separate crate and can't reach private items, so it really tests the public API. Testcontainers-style databases exist in both worlds. Ledgerly's is a small helper in crates/shared/src/database/testing.rs.

Check yourself

A test in crates/shared/tests/outbox.rs wants to call a pub(crate) helper. What happens?

  • It works; the file is in the same package
  • Compile error: integration tests see only pub items
  • It works only with the testing feature enabled
  • It works, but clippy warns about the visibility
Each tests/*.rs file is its own crate, outside ledgerly_shared.

What does original in any_money() mean inside proptest!?

  • Loop over a fixed list of money values
  • Run the test with many random generated values
  • Check whether original appears in the generated list
  • Use the single value that any_money returns
any_money() is a strategy (a generator), and proptest draws many inputs from it.

Why does just test run cargo test --doc after nextest?

  • Doc tests need a database that nextest doesn't start
  • nextest doesn't run doc tests, so they'd be skipped
  • Doc tests must run after all the other tests pass
  • cargo test is faster than nextest for doc examples
The recipe's comment says so: "nextest does not run those".
