Data types

Structs: like interfaces, plus data

A struct is the shape of an interface and the data of an object literal, but it has a name that matters and no optional fields.

By the end of this lesson

You can read Ledgerly's three kinds of struct (named fields, tuple struct, unit struct), build one, read its fields, and say why Expense has private fields while NewExpense has public ones.

Defining and building

  • Every field must be given. There's no ?:. A field that may be missing has the type Option<T> and you write None explicitly ().
  • Field init shorthand works like in JS: money, means money: money,.
  • Struct update syntax NewExpense { note: None, ..other } is like { ...other, note: undefined }, but the spread goes last.
  • #[derive(…)] generates standard abilities: printing with {:?}, cloning, comparing with ==. Lesson 50 covers it. For now, read it as "this struct can be debug-printed, copied and compared".

Public data vs guarded state

NewExpense is plain input data: all fields pub, anyone can build one. The Expense aggregate is the opposite:

No field is pub. Outside its module nobody can write expense.status = Approved or build an Expense { … } by hand. The only ways in are Expense::draft (which validates) and the six transition methods (which check the workflow). The doc comment above it says: "The fields are private and there is no setter."

Tuple structs and unit structs

  • Tuple struct: fields without names, accessed as .0, .1. Used for single-value wrappers ("newtypes", ): Merchant(String) is a String that's known to be a valid merchant.
  • Unit struct: no fields at all. InvalidId is an error that carries no data, only the fact that something wasn't a UUID.
Where the comparison breaks

TypeScript is structural: any object with the right fields is a NewExpense. Rust is nominal: two structs with identical fields are different, incompatible types. There are also no anonymous object literals. Every { … } value has a named struct type, and every field must be listed.

Check yourself

How do you say a struct field is optional?

  • note?: String
  • note: String | null
  • note: Option<String>
  • #[optional] note: String
Optional means "may be absent", which is Option<T>. You still pass the field, as None or Some(value).

Code in expenses::application has an expense: Expense. Which line compiles there?

  • expense.status = ExpenseStatus::Approved;
  • let s = expense.status;
  • let s = expense.status();
  • let e = Expense { ..expense };
The fields are private to the domain::expense module. Only the public method status() is reachable from application.

Two structs both have exactly { id: Uuid }. Can you pass one where the other is expected?

  • Yes, the shapes match so the types match
  • No, Rust compares struct types by their name
  • Only if they derive the same trait list
  • Only with an explicit as cast between them
Nominal typing. Ledgerly relies on it: TeamId and ExpenseId both wrap a UUID and are still different types.
