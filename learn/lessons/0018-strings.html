Strings: String vs &str

TypeScript has one string. Rust has two, because it cares who owns the bytes. This is your first taste of ownership.

By the end of this lesson

You can say why a Ledgerly function takes &str but returns String (or the other way round), convert between the two, and avoid the "length" trap that Ledgerly's text.rs exists for.

Rule of thumb, used throughout Ledgerly:

  • Parameters take &str: the function only reads, and callers can pass a literal or a &String.
  • Return String when you create new text, because the caller must own it.
  • Return &str when you hand back part of the input, with no copy.
  • Struct fields use String, because the struct must own its data.
In Ledgerly: all four rules in one file

strip returns a view of its input with the ends cut off, with no allocation. truncate_utf16 may add a '?', so it builds a new String.

Merchant owns its text (a String field). new borrows the input and copies the stripped part with to_owned(). as_str lends a view without copying.

Building text

The length trap

A Rust string is UTF-8 bytes. A JS string is UTF-16 units. They count differently:

TextJS .lengthRust .len() (bytes).chars().count()
"abc"333
"€"131
"😀"241

Java counts like JS, and Ledgerly's limits ("merchant at most 200") must match Java. That's why Merchant::new checks text::utf16_len(stripped) and not stripped.len(). For the same reason Rust won't let you write s[0]: a byte index could land in the middle of a character. Iterate with .chars() instead (Book 8.2).

Where the comparison breaks

JS strings are immutable values that the GC shares freely. Rust has to know who frees the bytes: String frees its buffer when it goes out of scope, and a &str must never outlive the text it points into. The compiler checks that (section 5). For now, read & as "borrowed, read only" and a type without & as "owned".

Check yourself

Why does strip(text: &str) return &str and not String?

  • &str is the only type functions can return
  • The result is part of the input, uncopied
  • String values can't contain whitespace characters at all
  • Returning String would need an unsafe block first
Trimming only moves the start and end of the view. Returning a borrowed slice avoids an allocation.

A struct needs to keep a user's name after the request ends. Which field type?

  • name: &str
  • name: String
  • name: char
  • name: &'static str
The struct must own its text. A &str field would borrow from something that may be gone. &'static str only fits text known at compile time.

What's "😀".len() in Rust?

  • 1
  • 2
  • 4
  • It doesn't compile
len() counts UTF-8 bytes. The emoji takes 4 bytes, 2 UTF-16 units (what JS and Java report) and 1 char.

How do you turn a &str into a String?

  • &text
  • text.to_owned()
  • text.as_str()
  • *text
to_owned() (or to_string(), String::from) copies the bytes into a new owned String. The others go the other way or don't compile.
