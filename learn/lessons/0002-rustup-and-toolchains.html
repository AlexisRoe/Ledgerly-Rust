Setting up and the toolbox

rustup and toolchains

rustup is nvm for Rust, and rust-toolchain.toml is the .nvmrc that pins Ledgerly to one exact compiler.

By the end of this lesson

You can read rust-toolchain.toml and mise.toml, say which Rust version Ledgerly builds with and why, and check your own setup with rustup show.

Warm-up: answer from memory first
What does rustc produce, and what runs it?
A native binary for one OS/CPU. Nothing "runs" it: no VM, no interpreter, no GC.
What replaces throw in Rust?
Returning a Result: Ok(value) or Err(error).

Ledgerly's pins

Whenever you run cargo anywhere inside the repo, rustup notices this file and uses exactly 1.99.1, installing it first if needed. profile = "minimal" means "only the compiler, cargo and std", and components adds the formatter and linter (rustup book: overrides).

mise is one level up: it pins every tool (Rust, just, Node for the OpenAPI linter, cargo plugins) like volta plus asdf. The comment says why Rust appears twice: rust-analyzer and plain cargo only read rust-toolchain.toml.

Editions: a dialect, not a version

The root Cargo.toml says edition = "2024". An edition is an opt-in set of language changes that would otherwise break old code: new keywords, changed defaults. A 2024-edition crate can depend on a 2018-edition crate without trouble. The compiler handles both (Edition Guide). Unlike tsconfig's target, it says nothing about the output: every edition compiles to the same machine code.

Where the comparison breaks

With nvm you switch Node by hand (nvm use) unless your shell hooks .nvmrc. rustup needs no hook: cargo and rustc are small rustup proxies that read rust-toolchain.toml on every call. So cd into another project can silently give you a different compiler.

Check yourself

You cd into Ledgerly and run cargo build. Which compiler version is used?

  • Exactly 1.99.1, as rust-toolchain.toml pins it
  • The newest stable you have installed
  • At least 1.99, per rust-version field
  • Whatever version mise last activated globally
rustup's proxies find rust-toolchain.toml by walking up from the current directory. rust-version = "1.99" in Cargo.toml is only a minimum check, like engines.

What is clippy to rustup?

  • A separate tool installed through npm
  • A component added to the toolchain
  • A dependency listed in each Cargo.toml
  • A feature flag of the compiler
Components ship with a toolchain version. rust-toolchain.toml asks for rustfmt and clippy, so everyone lints with the same version.

Ledgerly uses edition = "2024". A dependency uses edition 2018. What happens?

  • The build fails until both editions match
  • The dependency is upgraded to 2024 automatically
  • It just works; editions mix freely across crates
  • You need a nightly toolchain to mix them
Editions are per crate. One compiler understands all of them, and crates of different editions link together normally.
