Macros and attributes

Macros you'll meet

A name!(…) call is code that writes code at compile time. You'll use a dozen macros constantly and write almost none. This lesson is about reading them, including Ledgerly's one macro_rules!.

By the end of this lesson

You know what each everyday macro does and why it's a macro rather than a function, and you can read typed_id! well enough to add an eighth id type.

Why macros at all?

A Rust function has a fixed number of typed arguments. Macros can take any number of arguments, take syntax (a pattern, a format string, SQL) and check it at compile time. That's why println! can reject {nmae} before the program runs (Book 20.5).

Reading a macro_rules!

A declarative macro is pattern matching on code: each rule is (pattern) => { expansion }.

  • $name:ident captures an identifier (like TeamId) into $name.
  • $(#[$doc:meta])* captures zero or more attributes (the /// doc comment), and $(#[$doc])* repeats them in the output.
  • v7 and @common are literal tokens that select a rule. @common is a private helper rule called from the other two.

Each call expands into a complete newtype with all its impls. To add an id type, you'd add one more call.

Where the comparison breaks

TS has no macros. The closest things are code generators (OpenAPI, Prisma) that write files you can open. Macro output is invisible by default. To see it, hover the macro in VS Code and run rust-analyzer's "Expand macro recursively" command, or install cargo-expand. There are also procedural macros (derive, #[tokio::test], query_as!), Rust programs that transform code. Writing them is out of scope; reading their effect is enough.

Check yourself

Why can format!("{amount} EUR") catch a misspelled {amout} at compile time?

  • The editor checks strings while you type them
  • The macro parses the string while compiling
  • Rust strings are checked by the type system
  • clippy scans every string literal for names
A macro sees its input as syntax, so it can parse the format string and check each placeholder.

In typed_id!, what does $name:ident capture?

  • Any expression, such as a call's result
  • An identifier, such as TeamId or ExpenseId
  • A string literal containing the type's name
  • A UUID value used for the first id
ident is a fragment specifier for identifiers. Others include expr, ty, meta.

How do you see what typed_id!(TeamId, v7) expands to?

  • Read generated files in the target/ folder
  • Use the rust-analyzer command "Expand macro recursively"
  • Run the binary with a debug flag
  • It can't be seen; output stays invisible
rust-analyzer (or cargo expand) shows the expansion. No files are written.
