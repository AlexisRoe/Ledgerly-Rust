Traits and generics

derive and the standard traits

In JS every object can be logged, compared by reference and copied by reference. In Rust a type can do none of that until it implements the matching trait, usually with one #[derive(…)] line.

By the end of this lesson

You can read any #[derive(…)] line in Ledgerly and say what each name enables, and spot the traits a type deliberately leaves out.

derive generates the obvious implementation field by field. It only works if every field implements that trait too. Eq and Ord are the stricter versions: "equality is a true equivalence" (unlike floats, where NaN != NaN) and "every pair has an order" (Book appendix C).

In Ledgerly: what's derived, and what's missing
  • Role has no Ord, on purpose (lesson 22): "at least an approver" must go through includes.
  • Money has no Ord either: 1 EUR vs 1 USD has no answer, so comparison is the fallible Money::cmp returning a Result, and .sort() on mixed currencies can't compile.
  • Ids do have Ord: UUIDv7s sort by creation time, so sorting ids is meaningful.
  • Expense isn't Copy (it holds strings and a Vec) and isn't Hash (nobody needs it as a key).
  • Every type has Debug, except where it would leak secrets: SecretString prints [REDACTED] (lesson 71).

Where the comparison breaks

JS === compares objects by identity; two equal-looking objects are different. Rust's == (from PartialEq) compares values, field by field. That's why assert_eq!(expense, expected) in Ledgerly's tests works with no deep-equal helper. And when a trait is missing, the operation simply doesn't compile, which is how Ledgerly turns "don't compare money across currencies" into a type rule.

Check yourself

Which derive lets a type be a HashMap key?

  • Debug only
  • Clone + Copy
  • PartialEq + Eq + Hash
  • PartialOrd + Ord
A hash map needs to hash keys and compare them for equality. (BTreeMap would need Ord instead.)

Why can't you call .sort() on a Vec<Money>?

  • Vectors of structs can never be sorted
  • Money doesn't implement Ord, which sorting needs
  • Money is Copy; sort requires non-Copy types
  • Decimal values inside Money have no order
Deliberately: an order between currencies doesn't exist. Sort by amount within one currency with sort_by and Money::cmp.

What does {:?} need, and what does {} need?

  • Both need Display, written by hand each time
  • {:?} needs Debug, and {} needs Display
  • {:?} needs Display, and {} needs Debug
  • Both work for every type without traits
Debug is for developers (often derived), Display for users (always hand-written).
