Capstone: a service from scratch

Capstone 1: plan and set up

Over six lessons you build a small link-shortener service from an empty cargo new: domain types, a storage port, an HTTP API, a background worker, graceful shutdown. You write the code; the lessons give the decisions, tests to start from, and a reference solution to compare against afterwards.

By the end of this lesson

You have a new crate set up the way Ledgerly sets up its own (lints, formatting, dependencies), a module layout, and a list of requirements turned into types.

Errors are application/problem+json, like Ledgerly's. Storage is in memory, behind a trait, so a database could replace it.

Set up

  1. Outside the Ledgerly repository: cargo new shortlinks, then cd shortlinks. It's a binary crate (src/main.rs). Add src/lib.rs too: the logic goes in the library, so tests and main both use it.
  2. Dependencies: cargo add axum serde serde_json thiserror tokio tracing tracing-subscriber, then cargo add --dev tower http-body-util. Set features as in the solution's Cargo.toml below (serde needs derive, tokio needs macros, rt-multi-thread, net, signal, sync, time).
  3. Copy Ledgerly's rules: a [lints] table, a clippy.toml allowing unwrap in tests, and a rustfmt.toml with max_width = 120.
  4. Create empty modules domain, store, web and visits, declared in lib.rs. cargo check should pass.
Reference solution

Requirements to types

Before code, list the nouns and their rules. That list becomes your domain module (next lesson):

  • Slug: 3–32 characters of a-z, 0-9, -; never links (it would shadow GET /links/…); generated ones come from a counter.
  • Target: an http/https URL, trimmed, no spaces, at most 2048 bytes.
  • Link: a slug, a target, a visit count.
  • Errors: invalid input (400), slug taken (409), not found (404).
Where the comparison breaks

An Express project starts with npm init, then a choice of linter, formatter, test runner and TS config. A Rust project gets the compiler, formatter, linter, test runner and docs from cargo new; the setup work is choosing lint levels and dependencies' features.

Check yourself

Why put the logic in lib.rs modules rather than in main.rs?

  • Binaries cannot contain more than one module
  • Tests and main can both use the library
  • Libraries compile faster than binary crates do
  • Cargo requires every package to have a lib
main.rs stays a thin wiring layer, like Ledgerly's app crate.

Why is links a reserved slug?

  • Because slugs must never contain the letter s
  • GET /links would otherwise match the slug route
  • Because axum forbids that word in any path
  • Because short words are reserved for admins
A route and a slug sharing a namespace is a design decision to make early, in the type.
