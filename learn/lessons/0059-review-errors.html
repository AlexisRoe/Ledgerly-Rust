Mixed questions

Which line would clippy reject in Ledgerly's production code?

  • let n = text.parse::<u32>().unwrap_or(0);
  • let n = text.parse::<u32>().expect("number");
  • let n = text.parse::<u32>().map_err(|_| Invalid)?;
  • let n = text.parse::<u32>().ok();
expect panics on Err and is denied (expect_used). The others handle the error.

A ? on a Result<_, PersistenceError> compiles inside a function returning Result<_, UseCaseError>. Why?

  • All error types convert into each other
  • UseCaseError has a Storage variant marked #[from]
  • ? ignores error types, checking only Ok
  • PersistenceError is a type alias for UseCaseError
#[from] generated the From impl that ? uses. (55, 56)

(Traits) error.to_string() on an ExpenseError: where does the text come from?

  • The Debug output that derive generated for it
  • The Display impl that thiserror generated from #[error]
  • A message table loaded from the OpenAPI contract
  • The variant's name converted to sentence case
to_string exists for every Display type. thiserror wrote that Display. (50, 56)

(Ownership) Why does a refused approval leave the database unchanged?

  • The handler explicitly calls rollback in a catch block
  • ? returns early and the dropped transaction rolls back
  • Postgres ignores writes from requests that end in 409
  • approve() writes nothing until the very last line
The transaction is owned by the use case. The early return drops it, and drop rolls back. (Also: the domain checks before it assigns.) (36)

Trace a refusal yourself

Do this in VS Code (10 minutes)

A member (role MEMBER) calls POST …/expenses/{id}:approve on a colleague's submitted expense. Without re-reading lesson 58, find and write down:

  1. the line in Expense that refuses, and the exact ExpenseError value it returns;
  2. the UseCaseError variant it becomes, and why;
  3. the Problem constructor refusal picks, and the HTTP status;
  4. the message text the client sees.
Answer
require_decider in domain/expense.rs: actor.role().includes(Role::Approver) is false, so Err(Forbidden::RoleTooLow { role: Member, action: Approve }.into()), i.e. ExpenseError::Forbidden(…). The ? in TransitionExpense::execute wraps it as UseCaseError::Refused via #[from]. refusal matches ExpenseError::Forbidden(forbidden) → Problem::forbidden(…) → 403. Message: "Role MEMBER may not APPROVE". (A member may only see their own expenses, so in practice access::load answers 404 first for a colleague's expense. Both paths are worth knowing.)
