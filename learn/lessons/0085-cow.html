Ownership and lifetimes in depth

Cow: borrow when you can

Some functions usually return their input unchanged and occasionally need to build something new. Cow ("clone on write") lets one return type hold either, so the common case allocates nothing.

By the end of this lesson

You can return and consume a Cow<'_, str>, and read why Ledgerly's id deserialiser uses one.

The type

Just an enum with two variants (lesson 23). It implements Deref, so a Cow<str> can be used wherever a &str is expected: .len(), .chars(), ==, {}. Call .into_owned() when you need a String; it clones only if it was borrowed (std: Cow).

Writing one

Without Cow you'd choose between always returning String (an allocation on every call) and returning &str (impossible when you had to build new text).

In Ledgerly: ids read from JSON

'de is the lifetime of the input being deserialised. A JSON string without escapes can be borrowed straight out of the request body; one with escapes ("1…") must be decoded into a new String. Asking for Cow<'de, str> accepts both and allocates only when it must. Asking for &'de str would fail on escaped input; asking for String would always allocate.

Where the comparison breaks

JS strings are immutable and shared by the engine, so "return the input or a new string" costs nothing to express. Rust makes the cost visible, and Cow is how you avoid paying it on the common path. Don't use it everywhere: in most application code, returning String is simpler and fast enough. Measure first (lesson 109).

Check yourself

When does cow.into_owned() allocate?

  • Always, because it returns a new String value
  • Only if the Cow holds a borrowed value
  • Only if the Cow holds an owned value
  • Never; it reuses the original memory each time
Owned hands over its String; Borrowed must clone.

Why does the id deserialiser ask for Cow<'de, str> and not &'de str?

  • A &str can't be parsed into an id
  • Escaped JSON strings must be decoded into text
  • Cow makes the id parsing run in parallel
  • &str would leak all the request body's memory
Borrowing works only when the text appears as-is in the input.

You have a Cow<str> and want its length. What do you write?

  • cow.into_owned().len()
  • cow.len()
  • match cow { … } on both variants
  • cow.to_string().len()
Deref gives every &str method for free, without allocating.
