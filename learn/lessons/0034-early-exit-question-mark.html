Control flow

Early exit: return and ?

The ? operator is the most common control flow in Ledgerly. It replaces try/catch-and-rethrow with one character, and it's visible on every line that can fail.

By the end of this lesson

You can read a chain like .await?.ok_or(UseCaseError::NotFound)?, say exactly which line a function can leave from, and know where ? is allowed.

Warm-up
What does let Some(x) = opt else { return … }; do?
Binds x for the rest of the scope, or runs the else, which must leave. (33)
What does .ok_or(E) produce from an Option?
A Result: Ok(v) or Err(E). (24)

What ? does, exactly

expr? is shorthand for this match (Book 9.2, "the ? Operator"):

  • On Ok: unwrap the value and continue.
  • On Err: return from the enclosing function, converting the error into the function's error type through From (section 8 shows how Ledgerly sets those conversions up).
  • On an Option it works the same way: None returns None. It's only allowed in a function that itself returns Option.
  • ? works only in functions returning Result/Option. That's one reason main in Ledgerly matches by hand: it returns an ExitCode.

Read the chain top to bottom. .role_of(…) starts a database lookup. .await waits for it (lesson 62). ? leaves if the database failed. Now we have an Option<Role>: .ok_or(…) turns "not a member" into an error, and the second ? leaves with it. Each ? is a visible exit; in TS the first exit is an invisible throw somewhere inside roleOf.

In Ledgerly: three exits, one function

The merchant is checked first, then the note, then the date. The first failure returns, which is why the API reports "the first broken field in the order merchant, note, date". (transpose swaps Option<Result> into Result<Option> so ? can apply; lesson 47.)

Where the comparison breaks

A TS throw can come from any call, and nothing at the call site shows it. In Rust you can scan a function for ? and return and know every exit. (Panics are the exception, and Ledgerly bans the usual sources.) The cost is a ? on many lines; the gain is that error paths are part of reading the code.

Check yourself

In access::actor, a database error occurs in role_of. Which line ends the function?

  • The ok_or call, which handles every kind of error
  • The ? right after .await, returning the error
  • The final Ok(…), which wraps the error value
  • None of them; the error is silently ignored
The first ? sees Err and returns it, converted into a UseCaseError. ok_or only runs on success.

Can you use ? inside a function that returns u32?

  • Yes, it panics on errors in such functions
  • Yes, it returns zero when an error happens
  • No, the function must return a Result or Option
  • No, ? only works in async functions anyway
? needs somewhere to return the error to. The compiler error (E0277) says the function must return Result or Option.

What does ? do to the error before returning it?

  • Logs it at error level with its full message
  • Wraps it in a generic boxed error by default
  • Converts it to the function's error type via From
  • Nothing at all; the error types must match exactly
That's how a CurrencyError becomes a MoneyError inside Money::parse: there's a From conversion between them (lesson 55).
