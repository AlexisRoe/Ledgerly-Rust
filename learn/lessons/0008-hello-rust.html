Basic syntax and code organisation

Hello, Rust: fn main, let, mut, println!

Your first Rust program, and the three habits that differ from TypeScript right away: immutable by default, snake_case, and macros ending in !.

By the end of this lesson

You can write and run a small program that declares variables (mutable and not), defines constants and prints formatted output.

Warm-up
Which command builds and runs a binary?
cargo run (add --bin name when a package has several binaries).
What does cargo check do?
Type- and borrow-checks without producing a binary: the fastest feedback.

The smallest program

  • fn main() is the entry point of every binary. There's no top-level code outside functions.
  • let is TypeScript's const. A let binding can't be reassigned.
  • let mut is TypeScript's let. You must ask for mutability. The compiler warns if you write mut and never mutate.
  • println! is a macro, marked by the !. Macros generate code at compile time. println! checks its format string while compiling, so a typo in {nmae} is a compile error, not a runtime surprise. {name} inside the string works like ${name} in a template literal ( covers macros).
  • Statements end with ;, and it's not optional. The next lesson shows why it matters.

Where the comparison breaks

TS const only stops reassignment. You can still push into a const array. Rust's plain let is deeper: without mut you can't change the value at all, including its fields or elements. let v = Vec::new(); v.push(1); doesn't compile.

Check yourself

What's the Rust equivalent of TypeScript's let total = 0; that you later change?

  • let total = 0;
  • let mut total = 0;
  • const total = 0;
  • var total = 0;
Rust's let is immutable. Add mut to reassign or modify.

Why does println! end with !?

  • It may panic, so it's marked as dangerous
  • It's a macro that expands at compile time
  • It's an unsafe function from the C library
  • It prints right away without any output buffering
The ! marks a macro call. println! parses its format string at compile time, so placeholders that don't match are compile errors.

Which line does not compile?

  • let x = 1; let x = x + 1;
  • let x = 1; x = x + 1;
  • let mut x = 1; x += 1;
  • let x = 1; let x = "one";
Assigning to an immutable binding is error E0384. The other lines are shadowing (a new variable, any type) or a proper mut.

How would Rust name a function TypeScript calls parseDataSize?

  • ParseDataSize
  • parseDataSize
  • parse_data_size
  • PARSE_DATA_SIZE
Functions and variables are snake_case. Ledgerly really has a parse_data_size in crates/shared/src/config/.
