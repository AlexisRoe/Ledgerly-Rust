Data types

Option: no null, no undefined

T | undefined becomes Option<T>, an ordinary enum with two variants. Its methods replace ?. and ??.

By the end of this lesson

You can read Option fields and return types in Ledgerly, and the method chains on them (map, filter, ok_or, unwrap_or), translating each to the TS you'd write.

Warm-up
How does match get the data out of ExpenseError::Forbidden(…)?
With a pattern that binds a name: ExpenseError::Forbidden(forbidden) => ….
What do you write for a struct field that may be missing?
Option<T>. Every field must still be given, as None or Some(x).

It's just an enum

Generic over T (lesson 27), and in scope everywhere, so you write Some(x) and None without a prefix. A String can never be "null": if a value may be absent, its type says Option<String>, and you can't use the inner value without first handling None (Book 6.1, "The Option Enum").

In Ledgerly: filters that may or may not be set

Read it like a TS type: team is required (every query is scoped to a team!), and the rest are optional query filters such as ?status=SUBMITTED.

In Ledgerly: "found and visible, or not found"

Read the chain line by line. find returns an Option (after .await? handled the database error): Some(expense) or None. .filter turns Some into None if the actor may not see it. .ok_or turns None into the error NotFound. A missing expense, another team's expense, and a colleague's expense all look the same to the client, which is the security rule (OWASP API1) in four lines.

Where the comparison breaks

TS has two "nothing" values plus optional properties, and with strictNullChecks off, none of it is checked. Rust has one, it's a real type, and nesting means something: Option<Option<T>> can say "not given" vs "given as null", which T | null | undefined only hints at. (Ledgerly's PATCH takes a simpler route: note: None leaves the note alone, and a blank note removes it. See the match command.note in application/update_expense.rs.)

Check yourself

What's the Rust for TS note ?? "-", with note: Option<&str>?

  • note || "-"
  • note.unwrap()
  • note.unwrap_or("-")
  • note?.or("-")
unwrap_or gives the inner value or the fallback. unwrap() would panic on None.

What does .ok_or(UseCaseError::NotFound) do to an Option<Expense>?

  • Panics with NotFound if the option is None
  • Turns it into a Result, NotFound for None
  • Returns NotFound from the enclosing function right away
  • Logs NotFound and then returns the option unchanged
Some(e) becomes Ok(e), None becomes Err(NotFound). Returning early only happens if a ? follows.

Why is team in Criteria not an Option?

  • Option can't hold id types such as TeamId
  • Every query must be scoped to one team
  • The team is filled in later by the database
  • Options are only allowed at the end of structs
Ledgerly's rule: every query that reads team data takes the team id. The type makes an unscoped query impossible to build.
