The protocol, side by side

Same idea as JS's iterator protocol: Option replaces { value, done }. The difference is what you get afterwards. In JS (until iterator helpers land everywhere) you'd spread into an array to use .map. In Rust, Fibonacci::new().filter(|n| n % 2 == 0).take(3).sum() works immediately and allocates nothing.

IntoIterator: what for calls

for x in thing calls IntoIterator::into_iter(thing). Collections implement it three times: for Vec<T> (yields T, consumes the vector), &Vec<T> (yields &T) and &mut Vec<T> (yields &mut T). Give your own collection the same: impl<'a> IntoIterator for &'a Ledger, usually by returning the inner vector's .iter().

No struct needed: iter::from_fn

In Ledgerly: Java's readLine, as an iterator

The closure's captured rest is the iterator's state; each call returns the next line or None. Flyway checksums migrations by Java's line splitting rules (which differ from str::lines for a lone \r), so Ledgerly reimplements them. The caller then just does for line in java_lines(text).

Where the comparison breaks

A JS generator (function* with yield) is the most convenient way to write an iterator in TS. Stable Rust has no generators yet, so state that a generator keeps in local variables must live in struct fields or captured variables, as above.

Which methods must you write to give a type map, filter and sum?

  • All of them, one by one
  • Only next; the rest are defaults
  • next, plus size_hint and len
  • into_iter, plus next and collect
Every adapter is a default method built on next.

What does for line in &ledger require?

  • impl Iterator for Ledger
  • impl IntoIterator for &Ledger
  • impl Deref for Ledger
  • impl Index for Ledger
for calls into_iter on the expression, here a &Ledger.

The Pages iterator yields &'a [T]. Why 'a and not the lifetime of &mut self?

  • Because Iterator::next cannot take a mutable self
  • Pages borrow the slice, so outlive each call
  • Because slices always have the 'static lifetime
  • It makes each page a copy of data
The same idea as Words<'a> in lesson 81; collect needs it.
