Writing macros

macro_rules! from scratch

Lesson 61 taught you to read macro calls. A declarative macro is a match on syntax: each rule has a pattern of code fragments and a template that the matched fragments are pasted into.

By the end of this lesson

You can write a macro_rules! macro with fragment specifiers and simple repetition, and read Ledgerly's display_as_text!.

Warm-up

Anatomy

Macros work on syntax trees, not text: $value:expr captures a whole expression, so precedence can't leak the way it does with C's #define. Rules are tried top to bottom; the first match wins. Expansion happens at compile time, before type checking.

FragmentMatches
expran expression: 1 + 2, f(x), "text"
identa name: Merchant, prod_needs_the_database_url
tya type: Vec<u8>
literal"SPRING_DATASOURCE_URL", 42
metaattribute content, such as the doc = "…" inside #[…]
ttany single token tree: the escape hatch

Repetition

$( … ),* in a pattern matches zero or more comma-separated items (+: one or more, ?: optional). The same $( … )* in the template repeats once per match, using the variables captured inside.

In Ledgerly

Three identical Display impls, written once. The pattern takes one or more type names; the template repeats the whole impl block for each. Without the macro, a fix to one impl could easily miss the other two.

Where the comparison breaks

TS has no macros; you'd write a generic helper, a decorator, or a code generator script. Rust reaches for a macro when a function can't do the job: generating items (impls, structs, tests), taking a variable number of arguments, or checking something at compile time. If a function or a generic works, prefer it (lesson 120).

Check yourself

Why is square!(1 + 2) 9 even if the template were $value * $value?

  • Because Rust evaluates macro arguments only once
  • An expr fragment stays one expression, grouped
  • Because the compiler adds parentheses to all macros
  • It would actually be 5, like in C
Macros substitute syntax trees, not text. (The parentheses are still good style.)

What does $($name:ident),+ match?

  • Exactly one identifier, then a plus sign
  • One or more identifiers, separated by commas
  • Zero or more expressions, separated by commas
  • Any tokens at all, up to the bracket
+ = one or more; the separator is the , before it.

When does a macro expand?

  • At run time, each time the line executes
  • At compile time, before types are checked
  • At link time, after all crates are compiled
  • When the binary is loaded into memory
Then the expanded code is type-checked like hand-written code.
