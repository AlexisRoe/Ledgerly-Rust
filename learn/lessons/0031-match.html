match: a switch that checks everything

No fall-through, no forgotten break, and a compile error when a case is missing. This is the feature Ledgerly leans on hardest.

From switch + never to match

  • match value { pattern => expression, … }. Arms are tried top to bottom, and the first match wins. There's no fall-through and no break.
  • Exhaustive by default: if any possible value isn't covered, it's error E0004 and the compiler lists what's missing. No never trick needed.
  • match is an expression: its value is the chosen arm's value (here, the return value).

"From this status, where does this action lead?" for all 30 pairs. Notice the impossible actions are listed by name with | instead of a _ => None. That's on purpose (the doc comment says so): add a seventh Action and every inner match fails to compile until someone decides what it does from each status. A _ would silently answer None.

Where the comparison breaks

switch compares values with ===. match compares shapes: it can look inside enums, tuples and structs, bind parts of them, and check ranges, all at once. The next lesson shows destructuring. The trade-off to remember: _ buys convenience now at the price of the compiler's help later.

Check yourself

Someone adds Action::Archive. What happens to target_from?

  • It returns None for Archive from every status
  • It panics at runtime when Archive first arrives
  • Every inner match fails to compile for Archive
  • It routes Archive to each block's first arm
No arm covers Archive and there's no _, so each of the five inner matches is non-exhaustive (E0004).

What does Some(note) if is_blank(&note) => None match?

  • Any Some value; the if is a comment
  • A Some whose note is blank, nothing else
  • Every blank string, whether it's Some or None
  • A None value that was blank before parsing
The pattern must match and the guard must be true. A non-blank Some falls through to the next arm.

Which arm order is a mistake?

  • There is none; Rust reorders arms by specificity
  • The wildcard first makes the later arms unreachable
  • Ranges must always come after the single values
  • The 404 arm needs a guard, not a value
Arms are tried top to bottom. _ matches everything, so the compiler warns "unreachable pattern" for the other two.
