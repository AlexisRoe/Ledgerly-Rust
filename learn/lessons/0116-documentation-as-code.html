Designing Rust code

Documentation as code

Rust documentation lives next to the code, renders into a website with one command, and its examples are compiled and run as tests. Documentation that can't silently go stale changes how much people write.

By the end of this lesson

You can write doc comments with the standard sections, link items with intra-doc links, write doc tests that run, and generate the docs for Ledgerly and its dependencies.

The conventional shape

  • Standard headings: # Examples, # Errors (when it returns Result), # Panics (when it can panic), # Safety (for unsafe fn).
  • Intra-doc links: [`Name`] resolves like a use path; rustdoc warns if the target doesn't exist, so links survive renames.
  • Every ``` block is Rust by default and becomes a test that cargo test compiles and runs. Mark blocks ignore, no_run (compile only) or compile_fail (must not compile) (rustdoc: documentation tests).
In Ledgerly

Summary, the design reason, an intra-doc link to Ord::cmp, and an # Errors section. Ledgerly's docs are written for the next reader of the code, and very often explain the Java behaviour being matched.

Reading docs, yours and everyone's

The generated site for your exact dependency versions is often more useful than docs.rs: it matches your lock file and includes private items with --document-private-items.

Where the comparison breaks

TSDoc renders with TypeDoc, but its @examples are just text: nothing runs them, and they drift. Rust doc tests are real tests, and they compile against the crate's public API, exactly as a user would call it. They double as the best test of whether your API is pleasant to use.

Check yourself

A code block in a doc comment no longer compiles after a rename. When do you find out?

  • Never; examples in docs are plain text
  • At the next cargo test, as a failure
  • Only when someone opens the generated docs
  • When cargo publish uploads the crate later
Doc tests run with cargo test.

A function returns Result. Which doc section does convention expect?

  • # Returns
  • # Errors
  • # Throws
  • # Safety
Clippy's missing_errors_doc (pedantic) checks it.

What does [`MoneyError`] in a doc comment become?

  • Literal text with square brackets around it
  • A checked link to the MoneyError item's page
  • A footnote listing every single MoneyError variant
  • An import of MoneyError into the module
Intra-doc links resolve like paths, and rustdoc warns when they break.
