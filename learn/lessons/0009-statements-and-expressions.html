Functions

Parameters are name: Type, as in TS, and every parameter type is mandatory. The return type comes after ->. Without it the function returns (), the "unit" type, Rust's void. Ignore pub, const and self for now (lessons 13, 21, 44).

And the body has no return and no semicolon. That's the point of this lesson.

Expressions produce values, statements don't

Rust is an expression language: almost everything produces a value, including blocks { … }, if and match. The rule (Book 3.3):

  • A block's value is its last expression, if that expression has no semicolon.
  • Adding ; turns an expression into a statement, which produces (), i.e. nothing.
  • A function body is a block, so its last expression is the return value.

return x; still exists. Ledgerly uses it for early exits, as in main's Err(error) => return failed_to_start(&error). Idiomatic Rust uses no return for the final value.

In Ledgerly

The whole body of as_str is one match expression. Its value, a string, is the function's return value. Each arm Pattern => value, is also an expression.

In TypeScript you'd write a switch with a return in each case.

Where the comparison breaks

Arrow functions have a taste of this: (x) => x * 2 returns without return, but (x) => { x * 2 } returns undefined. In Rust it's the semicolon, not the braces, that decides, and it applies to every block: if branches, match arms, loops. The compiler catches the mistake (E0308) because the types don't line up.

What's the type of x in let x = { 5; };?

  • i32
  • ()
  • Option<i32>
  • It doesn't compile
The semicolon makes 5; a statement. The block has no final expression, so its value is (). (It compiles; clippy would complain.)

A function with no -> Type returns what?

  • Nothing; Rust functions can't return void
  • The unit value (), like void
  • Whatever its last expression evaluates to
  • An Option that is always None
The implicit return type is (). If the last expression has another type, that's a type error.

When does idiomatic Rust write return?

  • On every line that produces a result
  • Only to leave a function early
  • Only inside closures and async functions
  • Never; the keyword was removed in 2024
The final value is the last expression. return is for early exits, such as bailing out on an error.
