Basic syntax and code organisation

Imports with use

use is import { … } from, but paths are module paths separated by ::, starting from a crate, crate, super or self.

By the end of this lesson

You can read the block of use lines at the top of any Ledgerly file and say, for each name, whether it comes from the standard library, an external crate, a sibling Ledgerly crate, or this crate.

Paths and where they start

Every item has a path, like a file path with :: as separator. You can always write the full path inline (std::sync::Arc::new(x)). use creates a local shortcut so you can write Arc::new(x) (Book 7.4).

In Ledgerly: the imports of the expense endpoints

Read it top to bottom: standard library, then external crates (axum, sqlx), the sibling crate ledgerly_shared, then self::dto (the child module declared by mod dto; a few lines up), then crate::… (other modules of ledgerly_expenses). rustfmt sorts the groups.

The syntax, side by side

  • Rust has no default exports. Every name is named.
  • The convention: import types directly (use std::sync::Arc; → Arc), but import the module of a function (use ledgerly_shared::iso; → iso::format(…)), so the call site shows where the function comes from.
  • use super::*; appears in almost every mod tests: the tests see everything in the file they test, private items included (lesson 13).
Where the comparison breaks
  • use loads nothing. TS import also makes the file part of the program. In Rust that's mod's job (or the crate being in Cargo.toml). use only creates a name. You can even write use inside a function body to scope the shortcut.
  • Traits must be in scope to call their methods. Sometimes a use seems unused, like use std::fmt::Write as _; in build.rs. It's there so methods from the trait Write work on a String. More in .

Check yourself

Inside crates/expenses/src/web/mod.rs, what does crate::domain::Action refer to?

  • Action in the workspace's root crate ledgerly-app
  • Action in the domain module of ledgerly_expenses
  • Action in a crates.io crate named domain
  • Action in a sibling folder of web
crate is the root of the crate the file belongs to, here ledgerly_expenses. From there it's domain → Action.

What's the Rust spelling of import { strip as stripText } from "…/text"?

  • use text::{strip: strip_text};
  • use text::strip as strip_text;
  • use strip_text = text::strip;
  • use text::strip(strip_text);
as renames, also inside braces: use a::{b as c, d};.

A test module starts with use super::*;. What does it bring into scope?

  • Every item in the crate, public or not
  • Every item of the parent module under test
  • Only the public items of the standard library
  • Only the items whose names start with test
super is the parent: for mod tests in role.rs that's the role module. A child module can see its parent's private items.
