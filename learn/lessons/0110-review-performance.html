Mixed questions

Why is ExpenseId Copy while Merchant isn't?

  • Ids are used more often than merchants are
  • Ids are inline bytes; a merchant owns heap text
  • Merchant has a private field, and ids don't
  • Copy only works for types defined by macros
Copy means a bitwise copy is a full copy. Heap-owning types can't be. (38, 106)

(Iterators) Which allocates nothing?

  • rows.iter().map(|r| r.amount).collect::<Vec<_>>().iter().sum()
  • rows.iter().map(|r| r.amount).sum::<u64>()
  • rows.clone().into_iter().map(|r| r.amount).sum::<u64>()
  • rows.iter().map(|r| r.amount.to_string()).count()
Lazy adapters plus a consumer: no intermediate collection. (46, 107)

A colleague says "use dyn everywhere, generics bloat the binary". Your answer?

  • Agreed; dyn is always the better choice
  • dyn at seams, generics in hot inner code
  • Disagree; dyn always makes code much slower
  • Neither matters once LTO is turned on
Ledgerly's split: ports are dyn, iterators and serde are generic. (108)

(Async) A CPU-heavy CSV parse runs inline in a handler. What does a profile of the release build show?

  • Nothing, because profilers can't see async code
  • Time in the parser on a worker thread
  • Time spent waiting inside spawn_blocking calls instead
  • Only time spent in the database driver
Profilers sample threads; that worker is busy parsing. Then consider spawn_blocking. (104, 109)
