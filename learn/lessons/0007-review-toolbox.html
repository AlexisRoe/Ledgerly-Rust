Mixed questions

Which one of these is a real difference between running TS and running Rust?

  • Rust keeps type information around at runtime
  • Rust frees memory without a garbage collector
  • Rust needs a VM installed on the server
  • Rust has no async and await keywords
Ownership rules let the compiler insert frees at known points. Types are erased in both languages, Rust needs no VM, and it does have async/await (with a library runtime).

You see ledgerly-teams = { path = "crates/teams" }. Where are you, and what's the npm equivalent?

  • A member manifest; like a file: dependency
  • The root's workspace dependencies table; like workspace:*
  • The lock file; like a tarball URL
  • The toolchain file; like an engines entry
The root [workspace.dependencies] declares sibling crates by path. Members then write ledgerly-teams.workspace = true.

A teammate's PR has one rustfmt difference. Which command fails in CI?

  • just clippy
  • just fmt-check
  • just deny
  • cargo check
fmt-check runs cargo fmt --all --check, which fails without changing files. just fmt would fix it.

What does the release profile's lto = "fat" trade?

  • Safety checks for a faster binary at runtime
  • A slower build for a smaller, faster binary
  • Debug information for the more readable panic messages
  • Portability for a binary tied to one CPU
Whole-program link-time optimisation takes longer to build but produces better code. Safety checks are never traded away by a profile setting.

Why does Ledgerly use features = ["testing"] only under [dev-dependencies]?

  • Features cannot be used in normal dependencies
  • So tests run faster by skipping real code
  • So test helpers never compile into the binary
  • So cargo-deny can skip the testing crates
Code behind a feature isn't compiled unless something turns the feature on. Only the dev-dependencies (tests) do, so helpers like FixedClock can't leak into production.

Rank by speed of feedback, fastest first.

  • cargo check → just check → just verify
  • just check → cargo check → just verify
  • just verify → cargo check → just check
  • cargo check → just verify → just check
cargo check only analyses. just check adds formatting, lints, licences and tests. just verify adds the Docker-based parity suite on top.
