The change loop

Section 14 on one page. Pin it next to your editor.

Loop

  1. git switch -c practice/name (or a real branch for real work)
  2. Write or adjust the test first; see it fail (often a compile error first)
  3. Edit; save; read rust-analyzer's squiggles or cargo check -p <crate>
  4. Fix the first error, re-check. Repeat
  5. cargo test -p <crate> <filter> → then the whole crate → just test (Docker)
  6. cargo clippy -p <crate> --all-targets -- -D warnings · cargo fmt
  7. Query changed? just deps + just sqlx-prepare, commit .sqlx/
  8. Before committing: just check. Before a milestone: just verify
  9. Practice only: git restore . && git switch - && git branch -D practice/name

Reading an error

error[E0004]: headline → --> file:line:col → ^^^ the problem, --- related spots → note: context → help: suggested fix (check it: not todo!(), not _ on enums) → rustc --explain E0004.

Ledgerly's rules for real changes

  • Never modify vendor/, api/openapi.yaml, redocly.yaml, bruno/: contract and schema changes happen in Ledgerly-Java first.
  • Never weaken a parity test. Behaviour must match Java.
  • No unsafe; no unwrap/expect/panic!/todo! outside tests.
  • Secrets are SecretString from the moment they're read, never logged.
  • Every query that reads team data takes the team id.
  • One plan step, one Conventional Commit.
