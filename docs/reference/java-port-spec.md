# Ledgerly Java reference: module map (port spec)

Source root: `https://github.com/AlexisRoe/Ledgerly-Java/blob/e2a13909634808b347d30b3dec4c3ffee6741c02/src/main/java/com/ledgerly/` (abbreviated `J/` below).
Resources: `vendor/ledgerly-java/src/main/resources/` (`R/`). Stack: Spring Boot 4.2.0-RC2, Java 25, Spring Modulith 2.1.2
(events-jpa + events-jackson), Spring Batch 6, Bucket4j 8.22, Tika 4.2, AWS SDK v2 2.57 (`pom.xml`).

Every module is `@NullMarked`; public API = root package of the module + its `events` sub-package (`@NamedInterface("events")`).
Everything under `internal/` is private. `shared` is `@ApplicationModule(type = OPEN)` (`J/shared/package-info.java`).
Module-boundary verification: `ApplicationModules.of(LedgerlyApplication.class).verify()` (`src/test/java/com/ledgerly/ModularityTest.java`).

---

## 1. Modules: public API and internals

All event records share these rules: every event has `UUID eventId` (UUIDv7, generated by a convenience constructor
that omits it), `Instant occurredAt` (from the application `Clock`), ids only (no emails/amounts/names; ADR 0001).
Sealed interfaces so listeners can switch exhaustively.

### 1.1 identity (`J/identity/`)

Public API
- `IdentityFacade` (`J/identity/IdentityFacade.java`)
  - `Optional<UserSummary> find(UserId id)`
  - `default boolean isVerified(UserId id)` = `find(id).map(verified).orElse(false)`
  - Impl: `internal/application/IdentityFacadeImpl` (`@Transactional(readOnly)`, reads `users` by id).
- `record UserSummary(UserId id, String email, boolean verified)` (`J/identity/UserSummary.java`). Email is for invitation matching only.
- Events (`J/identity/events/`): `sealed interface IdentityEvent permits UserRegistered, UserVerified, RefreshTokenReuseDetected`
  with `UUID eventId(); UserId actorId(); Instant occurredAt()`. No team.
  - `record UserRegistered(UUID eventId, UserId actorId, Instant occurredAt)`
  - `record UserVerified(UUID eventId, UserId actorId, Instant occurredAt)`
  - `record RefreshTokenReuseDetected(UUID eventId, UserId actorId, UUID familyId, Instant occurredAt)`
- Module-internal event (NOT public): `internal/application/VerificationLinkIssued(UUID userId, String token)`
  (carries the raw verification token; `toString` masks token; only listener: `LocalVerificationLogger`, profile `local & !test`,
  logs `"[local only] verify user {} with POST /api/v1/auth/verify {\"token\":\"{}\"}"`).

Internal packages
- `internal/OwnTokenIssuing` – meta-annotation = `@Profile("!keycloak")`; marks register/verify/login/refresh/logout, keys, JWKS, password encoder.
- `internal/application`: `Register`, `VerifyEmail`, `Login`, `Refresh`, `Logout`, `Session(accessToken, expiresInSeconds, refreshToken, refreshTtl)`,
  `AccessTokenIssuer`, `OpaqueTokens`, `ExternalIdentityProvisioner` + `ExternalSubjectJwtConverter` (profile `keycloak`), `LocalVerificationLogger`.
- `internal/domain`: `User`, `RefreshToken`, `EmailVerification` (JPA entities).
- `internal/infrastructure`: `AuthProperties`, `IdentityConfig` (PasswordEncoder, JwtKeys, JwtEncoder, JwtDecoder), `JwtKeys`,
  `KeycloakResourceServerConfig`, repositories (`UserRepository`, `RefreshTokenRepository`, `EmailVerificationRepository`).
- `internal/web`: `AuthController` (`/api/v1/auth/{register,verify,login,refresh,logout}`), `JwksController` (`/.well-known/jwks.json`),
  `SecurityConfig` (the global security filter chains; lives in identity).
- Tables: `users`, `email_verifications`, `refresh_tokens` (V3, V9, V10).

### 1.2 teams (`J/teams/`)

Public API
- `TeamsFacade` (`J/teams/TeamsFacade.java`): `Optional<Role> roleOf(TeamId teamId, UserId userId)` (empty = not a teammate).
  Impl `internal/application/TeamsFacadeImpl` (readOnly tx, memberships by PK).
- Bean by name `teamAuthorization` (`internal/application/TeamAuthorization`) used from SpEL `@PreAuthorize` by **other modules' controllers**
  (audit) – an implicit runtime dependency not visible as a code dependency:
  - `boolean anyOf(UUID teamId, String... roles)` – caller's role must be exactly one of them; not member -> `NotFound`, wrong role -> `Forbidden("Role X may not do this")`.
  - `boolean atLeast(UUID teamId, String role)` – ladder check via `Role.includes`.
- Events (`J/teams/events/TeamEvent.java`): `sealed interface TeamEvent` with `UUID eventId(); TeamId teamId(); UserId actorId(); Instant occurredAt()`; nested records:
  - `TeamCreated(UUID eventId, TeamId teamId, UserId actorId, Instant occurredAt)`
  - `MemberInvited(UUID eventId, TeamId teamId, UserId actorId, UUID invitationId, String role, Instant occurredAt)`
  - `InvitationRevoked(UUID eventId, TeamId teamId, UserId actorId, UUID invitationId, Instant occurredAt)`
  - `InvitationAccepted(UUID eventId, TeamId teamId, UserId actorId, UUID invitationId, Instant occurredAt)`
  - `InvitationDeclined(UUID eventId, TeamId teamId, UserId actorId, UUID invitationId, Instant occurredAt)`
  - `MemberRoleChanged(UUID eventId, TeamId teamId, UserId actorId, UserId memberId, String oldRole, String newRole, Instant occurredAt)`
  - `MemberRemoved(UUID eventId, TeamId teamId, UserId actorId, UserId memberId, Instant occurredAt)`
  - `MemberLeft(UUID eventId, TeamId teamId, UserId actorId, Instant occurredAt)`

Internal packages
- `internal/application`: `CreateTeam`, `InviteMember`, `RevokeInvitation`, `AcceptInvitation`, `DeclineInvitation`, `ChangeMemberRole`,
  `RemoveMember`, `LeaveTeam`, `GetMe` (serves `GET /api/v1/me` – in teams so identity never depends on teams, "decision D5"),
  `InvitationResponses`, `InvitationView`, `TeamGuard` (team-row `SELECT ... FOR UPDATE` lock + last-owner rule), `TeamAuthorization`.
- `internal/domain`: `Team`, `Membership`, `MembershipId(teamId,userId)`, `Invitation`, `InvitationStatus {PENDING, ACCEPTED, DECLINED, REVOKED, EXPIRED}`
  (EXPIRED never stored, computed: `PENDING && !expiresAt.isAfter(now)`).
- `internal/infrastructure`: repositories, `TeamsProperties(ledgerly.teams.invitation-ttl = 7d)`.
- `internal/web/TeamsController` (implements generated `TeamsApi`, `MeApi`).
- Tables: `teams`, `memberships`, `invitations` (V4). Emails normalised `strip().toLowerCase(Locale.ROOT)`.

### 1.3 expenses (`J/expenses/`)

Public API
- `ExpensesFacade` (`J/expenses/ExpensesFacade.java`), impl `internal/application/ExpensesFacadeImpl`:
  - `void requireCanView(TeamId teamId, ExpenseId expenseId, UserId caller)` – throws `NotFound` unless teammate who may see it (claimant, or role >= APPROVER).
  - `void requireCanChangeReceipts(TeamId teamId, ExpenseId expenseId, UserId caller)` – `NotFound` if not visible; then domain `NotAllowed` (403 FORBIDDEN) unless claimant, `NotDraft` (409) unless DRAFT.
  - `Optional<ValidationProblem> validate(NewExpense expense)` – runs merchant/note/date field rules without writing.
  - `List<ExpenseId> createDrafts(TeamId teamId, UserId claimant, List<NewExpense> expenses)` – one tx; `InvalidRequest("items", "Between 1 and {maxBatchSize} expenses at a time")` if empty/too many (checked BEFORE membership); `NotFound` if claimant not teammate; publishes one `ExpenseEvent.Created` per id (actor = claimant).
- `record NewExpense(Money money, Category category, LocalDate incurredOn, String merchant, @Nullable String note)`
- `record ValidationProblem(String field, String message)`
- `enum Category { TRAVEL, MEALS, OFFICE, SOFTWARE, OTHER }`
- **Owned interface implemented by receipts**: `ReceiptChecks` (`J/expenses/ReceiptChecks.java`): `ReceiptSummary summaryFor(ExpenseId expenseId)`;
  `record ReceiptSummary(int accepted, int pendingScan)` (negative -> IllegalArgumentException).
- Events (`J/expenses/events/ExpenseEvent.java`): `sealed interface ExpenseEvent` with `UUID eventId(); TeamId teamId(); ExpenseId expenseId(); UserId actorId(); Instant occurredAt()`; records
  `Created, Deleted, Submitted, Withdrawn, Approved, Rejected, Reopened, Reimbursed` all `(UUID eventId, TeamId teamId, ExpenseId expenseId, UserId actorId, Instant occurredAt)`,
  and `Edited(UUID eventId, TeamId teamId, ExpenseId expenseId, UserId actorId, List<String> changedFields, Instant occurredAt)`
  (`changedFields` subset of `money, category, incurredOn, merchant, note` in that order; may be empty – event still published).

Internal packages
- `internal/application`: `CreateExpense` (idempotency), `GetExpense`, `UpdateExpense`, `DeleteExpense`, `TransitionExpense`, `ListExpenses`,
  `BatchCreateExpenses`, `ExportExpenses`, `ExpenseAccess`, `ExpenseFilters`, `ExpenseView`, port `MembershipLookup` (adapter `infrastructure/TeamsMembershipLookup` -> `TeamsFacade`).
- `internal/domain`: `Expense` (aggregate, `@Version long version`), `ExpenseStatus {DRAFT, SUBMITTED, APPROVED, REJECTED, REIMBURSED}`, `Action {SUBMIT, WITHDRAW, APPROVE, REJECT, REOPEN, REIMBURSE}`,
  `Actor(UserId, Role)`, `Rejection(UserId rejectedBy, String reason)`, sealed `ExpenseException` -> `InvalidTransition`, `SelfDealing`, `NotAllowed`, `RuleViolated`, `InvalidInput(field)`, `NotDraft`.
- `internal/infrastructure`: `ExpenseRepository` (extends bare `Repository`, every lookup team-scoped), `ExpenseSpecifications`, `TeamsMembershipLookup`.
- `internal/web`: `ExpensesController`, `ExpenseMapper`, `ExpenseDomainExceptionHandler` (`@Order(HIGHEST_PRECEDENCE)`), `CsvCells`, `LazyCsvInputStream`.
- Tables: `expenses`, `expense_rejections` (V1).

Domain rules (for parity): merchant required, stripped, <= 200 chars; note <= 2000 (not stripped; blank note in PATCH clears to null);
reject reason required, stripped, <= 1000; `incurredOn` not after `LocalDate.now(clock)` (UTC clock).
Transitions: SUBMIT (claimant, DRAFT, needs accepted>=1 else `RuleViolated("At least one accepted receipt is required to submit")`, pendingScan>0 -> `RuleViolated("Receipts are still being scanned")`);
WITHDRAW (claimant, SUBMITTED->DRAFT); APPROVE/REJECT (role>=APPROVER, not claimant -> `SelfDealing`, SUBMITTED); REOPEN (claimant, REJECTED->DRAFT);
REIMBURSE (role OWNER, not claimant, APPROVED). Check order: role/claimant first, then status. Domain -> error mapping:
InvalidTransition->EXPENSE_INVALID_TRANSITION, SelfDealing->EXPENSE_SELF_DEALING, NotDraft->EXPENSE_NOT_DRAFT, NotAllowed->FORBIDDEN,
RuleViolated->EXPENSE_RULE_VIOLATED, InvalidInput->VALIDATION_FAILED with `errors:[{field,message}]` (`internal/web/ExpenseDomainExceptionHandler.java`).
Metric `ledgerly.expenses.transitions{action=<lowercase>}`.

### 1.4 receipts (`J/receipts/`)

Public API
- No facade. Implements `expenses.ReceiptChecks` via `internal/application/ReceiptChecksImpl` (counts `ACCEPTED` and `PENDING_SCAN` rows by `expense_id`).
- Events (`J/receipts/events/ReceiptEvent.java`): `sealed interface ReceiptEvent` with `UUID eventId(); TeamId teamId(); ExpenseId expenseId(); UUID receiptId(); Instant occurredAt(); default @Nullable UserId actorId() = null`:

- Module-internal event: `internal/application/ReceiptUploaded(UUID receiptId)` (triggers the scan).

Internal packages

- `internal/domain`: `Receipt`, `ScanStatus {PENDING_SCAN, ACCEPTED, QUARANTINED}`.
- `internal/infrastructure`: `ClamAvScanner` (`@Profile("!test")`), `ReceiptRepository`, `ReceiptsProperties`, `ReceiptsConfig` (`@EnableAsync`, `@EnableResilientMethods`).
- `internal/web/ReceiptsController`: upload (202 + Location `/api/v1/teams/{t}/expenses/{e}/receipts`), list, delete (204), download (`Cache-Control: no-store`, `{url, expiresAt}`).

## 2. Module dependencies

Code/bean dependencies (from source and `docs/modules/components.puml`, `docs/modules/module-*.adoc`):

- identity -> shared (only).
- teams -> identity: `IdentityFacade.find` (in `GetMe`, `InvitationResponses`). teams -> shared.
- expenses -> teams: `TeamsFacade.roleOf` (via `MembershipLookup` adapter `TeamsMembershipLookup`). expenses -> shared (`IdempotencyStore`, `LedgerlyLimits`, `ProblemFactory`, `CurrentUser`).
- expenses -> receipts: **none at compile time**. Expenses calls `ReceiptChecks` (an interface it owns); receipts provides the bean.
- receipts -> expenses: `ExpensesFacade.requireCanView / requireCanChangeReceipts`; implements `ReceiptChecks`; listens to `ExpenseEvent.Deleted`. receipts -> shared (`ObjectStorage`, `LedgerlyLimits`, `CurrentUser`).
- imports -> teams: `TeamsFacade.roleOf` (`UploadImport`, `GetImport`). imports -> expenses: `ExpensesFacade.validate` (`RowProcessor`), `ExpensesFacade.createDrafts` (batch writer). imports -> shared.
- audit -> listens to identity, teams, expenses, receipts, imports events. audit -> shared (`LedgerlyLimits`, paging). audit -> teams **by bean name only** (`@teamAuthorization` SpEL), no code import.
- shared -> nothing (but `shared/seed/DevDataSeeder` writes directly via SQL into users/teams/memberships/invitations/expenses/expense_rejections, `local & !test` profile).

Listener list (cross-module):
- receipts `ExpenseDeletedCleanup.on(ExpenseEvent.Deleted)` (`@ApplicationModuleListener`).
- audit `AuditListeners.on(...)` for all 25 public event types (`@ApplicationModuleListener`).

Intra-module listeners: receipts `ScanReceipt.on(ReceiptUploaded)`; imports `ImportRunner.on(ImportQueued)`; identity `LocalVerificationLogger.on(VerificationLinkIssued)` (plain `@EventListener`, synchronous).

Cycles avoided by inversion:
1. expenses <-> receipts: submit needs receipt counts (expenses -> receipts), upload needs draft check (receipts -> expenses).
   Resolved by expenses owning `ReceiptChecks`/`ReceiptSummary`, receipts implementing it (ADR 0002, `docs/adr/0002-expenses-asks-receipts-through-an-interface-it-owns.md`).
   Rust: put `trait ReceiptChecks` in the expenses crate; receipts crate implements it; wire at the app/composition root.
2. identity <-> teams: `/me` needs teams + account, so `GetMe` lives in teams and calls `IdentityFacade` (identity never depends on teams).
3. expenses -> teams via own port `MembershipLookup` (adapter in infrastructure) – a seam, not strictly needed for acyclicity.
4. Audit authorizes via `teamAuthorization` bean name to avoid audit -> teams code dependency (Rust: inject an `Authorizer`/`TeamsFacade` trait object, or check in an app-level guard).
5. Commands across modules go through facades (ADR 0003, `createDrafts`); events are only for reactions.

## 3. Cross-cutting pieces in `shared`

### 3.1 Ids (`J/shared/id/`)
- `UserId(UUID)`, `TeamId(UUID)` records; JPA `AttributeConverter`s autoApply to plain `uuid` columns. `ExpenseId(UUID value)` is `@Embeddable` (column `id`). `toString()` = bare UUID string (matters for idempotency hash, see 3.4).
- `UuidV7.generate()` (`J/shared/id/UuidV7.java`): `SecureRandom`; uses `System.currentTimeMillis()` (NOT the injected Clock);
  `msb = (millis << 16) | 0x7000 | (rand.nextLong() & 0x0FFF)`; `lsb = (rand.nextLong() & 0x3FFFFFFFFFFFFFFF) | 0x8000000000000000`.
  i.e. RFC 9562 v7, 48-bit ms timestamp, version 7, 12 random `rand_a` bits, variant `10`, 62 random bits. No monotonic counter / no intra-ms ordering guarantee.
- Where v7 is used: `ExpenseId.random()`, `User.id`, `EmailVerification.id`, `RefreshToken.id`, `Team.id`, `Invitation.id`, `Receipt.id`, `audit_events.id`, every event `eventId`, seeder ids.
- Where **random v4** (`UUID.randomUUID()`) is used: `TeamId.random()`/`UserId.random()` (despite the "time-ordered" doc comment; not used in main code), refresh-token `family_id` (on login),
  JWT `jti`, generated JWK `kid` (local/test only), receipt storage key `receipts/<v4>`, quarantine key `quarantine/<v4>`, import storage key `imports/<v4>`, **import id** (`import_jobs.id`).
- Demo team id fixed: `00000000-0000-7000-8000-00000000a001` (`J/shared/seed/DevDataSeeder.java`).

### 3.2 Money (`J/shared/money/Money.java`)
- `record Money(BigDecimal amount, Currency currency)`; columns `amount numeric(19,4)`, `currency char(3)`.
- Rejects currencies with `getDefaultFractionDigits() < 0` (XAU, XTS, XXX...): "Not a monetary currency: X".
- Amount must be `> 0` ("Amount must be positive: x"); `stripTrailingZeros().scale()` must be <= currency digits ("Amount A has more than D decimal places for C").
- Normalised with `setScale(digits)` (so `12.5 EUR` -> `12.50`; `1000 JPY` scale 0). Equality is value equality after normalisation.
- `Money.of(String, String)`, `plus` / `compareTo` throw `CurrencyMismatch("Currency mismatch: L vs R")` on different currencies.
- API representation: `{"amount": amount.toPlainString(), "currency": "EUR"}` (string, never float). Parse failures (bad number, bad code, rule) -> `InvalidRequest(field "money", message)`; `NumberFormatException` message replaced by `"Not a valid decimal number"`.

Exception classes (sealed `LedgerlyException(error, detail, violations)`), fixed details:
- `NotFound()` -> NOT_FOUND, "Resource not found". `Unauthenticated()` -> "Authentication required".
- `Forbidden(detail)` / `Forbidden(ErrorCatalogue, detail)`. `Conflict(ErrorCatalogue, detail)`. `Unprocessable(ErrorCatalogue, detail[, violations])`.
- `PreconditionFailed()` -> "The resource changed since you read it". `PreconditionRequired(header)` -> "The {header} header is required".
- `PayloadTooLarge(detail)`, `UnsupportedMedia(detail)`, `TooManyRequests(detail, Duration retryAfter)` -> RATE_LIMITED.

`ProblemFactory.create(error, detail?, violations)` (`ProblemFactory.java`): RFC 9457 body
`{type, title, status, detail?, instance?, code, traceId?, errors?}`; `code` = enum name; `traceId` from current Micrometer span if any;
`errors` = `[{field, message}]` only when non-empty. `enrich()` adds `code: "REQUEST_REJECTED"` (+ traceId) to Spring-generated problems lacking a code (404 unknown path, 405, 415...).
Content-Type `application/problem+json`.

`ProblemExceptionHandler` (`@RestControllerAdvice @Order(LOWEST_PRECEDENCE)`):
- LedgerlyException -> its problem; `TooManyRequests` adds `Retry-After: max(1, retryAfter.toSeconds())` (truncating seconds).
- Optimistic lock failures -> 412 PRECONDITION_FAILED.
- `ConstraintViolationException` -> 400 VALIDATION_FAILED, field = last segment of property path.
- `MethodArgumentNotValid` / `HandlerMethodValidation` -> 400 VALIDATION_FAILED with violations (parameter name or "request").
- Unreadable body -> 400 MALFORMED_REQUEST "The request body is missing, malformed or contains unknown fields" (unless a `PayloadTooLarge` is in the cause chain -> 413). Unknown JSON fields are rejected (`spring.jackson.deserialization.fail-on-unknown-properties: true`).
- Missing header: `If-Match` -> 428 PRECONDITION_REQUIRED "The If-Match header is required"; other headers -> 400 VALIDATION_FAILED `[{field: <header>, message: "header is required"}]`.
- Multipart too large -> 413 "The upload is larger than the limit".
- Anything else -> logged `"Unhandled exception"` + 500 INTERNAL_ERROR with no detail.

Security-filter errors (`J/shared/security/ProblemSecurityHandler.java`), same body + `instance = request URI`:
- 401: header `WWW-Authenticate: Bearer`, detail "Authentication required".
- 403: detail "Access denied".
- 429 from filters: `Retry-After = max(1, ceil(retryAfterMillis/1000))` (ceil, unlike the controller path), detail "Too many requests; slow down".

Expense domain exceptions are mapped by `expenses/internal/web/ExpenseDomainExceptionHandler` (see 1.3). Domain-specific details used elsewhere:
`LAST_OWNER` ("A team must keep at least one owner" / "The last owner cannot leave; promote someone else first"), `ALREADY_MEMBER` ("You are already a teammate"),
`INVITATION_EXPIRED` ("This invitation has expired"), `INVITATION_NOT_PENDING` ("This invitation is {STATUS}" / "Only a pending invitation can be revoked"),
`EMAIL_NOT_VERIFIED` ("Verify your email address before accepting"), `RECEIPT_DUPLICATE` ("This file is already attached to the expense"),
`BATCH_REJECTED` ("Nothing was created because some items are invalid", violations field `items[i]` or `items[i].<field>`).

### 3.4 Idempotency (`J/shared/idempotency/IdempotencyStore.java`, used only by `expenses/internal/application/CreateExpense.java`)
- Header `Idempotency-Key`, optional, 8..128 chars (`api/openapi.yaml` `IdempotencyKey`). Only on `POST /api/v1/teams/{teamId}/expenses`.
- Table `idempotency_keys(user_id uuid, idem_key varchar(128), request_hash char(64), response_status int, resource_id uuid, created_at, expires_at)`, PK `(user_id, idem_key)` (V2). Keys are per user; raw key stored (not hashed).
- TTL 24h: `expires_at = now + 24h` (application Clock). `find` filters `expires_at > now`. `save` first deletes this user's expired row for the key, then inserts; PK clash -> `DuplicateKeyException` -> 409 IDEMPOTENCY_IN_PROGRESS "A request with this Idempotency-Key is in progress". No background purge job (index on `expires_at` only).
- **Request hash** = lower-case hex SHA-256 of UTF-8 bytes of Java record `CreateExpense.Command.toString()`:
  `Command[teamId=<uuid>, claimantId=<uuid>, money=Money[amount=<BigDecimal.toString of normalised amount>, currency=<ISO code>], category=<ENUM>, incurredOn=<yyyy-MM-dd>, merchant=<raw merchant as received, unstripped>, note=<raw note or null>]`
  (Java record toString: `Name[f1=v1, f2=v2]`, `", "` separators, null -> `null`). A byte-compatible port must reproduce this string exactly to honour keys stored by Java during the 24h window.
- Flow: membership check (404) -> if key present and row found: hash differs -> 422 IDEMPOTENCY_KEY_REUSED "This Idempotency-Key was used with a different request"; same -> re-read the expense **as it is now** (not a byte copy) and return it (status 201, replayed); expense gone -> 409 IDEMPOTENCY_IN_PROGRESS "The expense created by this key no longer exists".
  Otherwise create, publish `Created`, then save entry `(hash, 201, expenseId)` in the same tx.

### 3.5 ETag / If-Match (`J/expenses/internal/web/ExpensesController.java`)
- ETag = `"<version>"` (strong, quoted JPA `@Version` long, starts at 0). Sent on create (201 + `Location: /api/v1/teams/{t}/expenses/{id}`), get, update, transitions.
- `If-Match` required (428 if missing) on `PATCH` and `DELETE` of an expense; parse: strip, drop leading `W/`, drop surrounding quotes, `Long.parseLong`; unparseable -> 412. Version mismatch -> 412. Concurrent optimistic-lock failures -> 412.
- Transitions do not take If-Match. Max header length 64 (openapi).

### 3.6 Paging
- Offset paging for expenses list (`ListExpenses`): `page` >= 0, `size` 1..`maxPageSize`; `sort=field[,asc|desc]` (default desc), fields `incurredOn | createdAt | amount` (amount requires a `currency` filter), tie-breaker `id` same direction.
  Response `{content, page:{size, number, totalElements, totalPages}}` (`ExpensePage` in the spec, `PageMetadata(size, number, totalElements, totalPages)`). MEMBERs are forced to their own expenses (claimantId filter ignored); `incurredFrom > incurredTo` -> 400 field `incurredFrom`; unknown currency -> 400 field `currency`.
- Keyset paging (`J/shared/paging/KeysetPaging.java`), used by audit: `select * from <table> where team_id=:team [and (created_at, id) < (:ts, :id)] order by created_at desc, id desc limit :limit+1`; `next` cursor from last returned row, null on the last page.
- **Cursor encoding** (`J/shared/paging/Cursor.java`): JSON `{"t": Instant.toString(), "id": uuid}` (Jackson writes `Map.of` – key order not guaranteed: decoders must accept either order) -> UTF-8 -> Base64url **without padding**.
  `Instant.toString()` is ISO-8601 UTC with `Z`, trailing-zero fractional groups trimmed to 0/3/6/9 digits (e.g. `2026-11-12T10:15:30.123456Z`; Postgres timestamptz has µs precision). Decode errors of any kind -> 400 VALIDATION_FAILED field `cursor` "Invalid cursor". Audit: `limit` 1..maxPageSize else field `limit`; blank `after` = first page. Response `{items, nextCursor?}`.
- CSV export (`ExportExpenses`, `LazyCsvInputStream`, `CsvCells`): pages of 500, cap `maxExportRows`, sort `incurredOn desc, id desc`; headers `Content-Type: text/csv;charset=UTF-8`, `Content-Disposition: attachment; filename="expenses.csv"`, `X-Total-Count`, `X-Truncated` (`true`/`false`), `Cache-Control: no-store`.
  Columns `id,incurredOn,merchant,amount,currency,category,status,claimantId,note`, CRLF line ends; cells starting with `= + - @ \t \r` get a leading `'`; quote cell (doubling `"`) if it contains `, " \n \r`.

### 3.7 Security config (`J/identity/internal/web/SecurityConfig.java`, filters in `J/shared/security/`, `J/shared/web/`)
Servlet filter order:
1. `JsonBodyLimitFilter` (`@Order(HIGHEST_PRECEDENCE)`, before Spring Security): only for JSON content types (`application/json`-compatible, subtype `json`, or `*+json`). `Content-Length > maxJsonBodySize` (1 MB = 1,048,576 bytes) -> immediate 413 with `Connection: close`, detail "The request body is larger than {limit} bytes"; else counts bytes while reading (chunked) and throws the same 413.

Origins validated at startup against `^https?://[A-Za-z0-9.-]+(:[0-9]{1,5})?$`.

   - `AuthRateLimitFilter` (before `BearerTokenAuthenticationFilter`): only URIs starting `/api/v1/auth/`; bucket scope `auth-ip`, key `request.getRemoteAddr()`; `authRequestsPerMinute` (60) greedy refill.

   - `MdcTeamFilter` (after MdcUser): MDC `teamId` from URI `^/api/v1/teams/(<uuid>)(?:[/:].*)?$`.

- Login lockout: scope `login`, key = normalised email, `intervally(maxFailedLogins=5, lockDuration=15m)`; checked `isExhausted` before anything; failure consumes a token; success `reset`.
- CSRF for cookie endpoints (ADR 0004): `POST /api/v1/auth/refresh` and `/logout` require `X-Requested-With: ledgerly` (missing -> 400 VALIDATION_FAILED header required; wrong value -> 400 VALIDATION_FAILED field `X-Requested-With` "must be 'ledgerly'").

## 4. Crypto / encoding details (data compatibility)

- **Passwords**: `Argon2PasswordEncoder.defaultsForSpringSecurity_v5_8()` (`identity/internal/infrastructure/IdentityConfig.java`) = Argon2**id**, salt 16 bytes, hash 32 bytes, parallelism 1, memory 16384 KiB (m=16384), iterations 2, version 0x13 (Bouncy Castle).
  Stored PHC string `$argon2id$v=19$m=16384,t=2,p=1$<salt>$<hash>` with salt/hash in **standard Base64 without padding** (Spring's `Argon2EncodingUtils`). Column `users.password_hash varchar(255)`, nullable since V10 (external accounts).
  Timing equalisation: Login verifies against a dummy hash of `"not-a-real-password"` for unknown emails; Register hashes before the existence check. Password length is enforced only by bean validation generated from `api/openapi.yaml` (400 VALIDATION_FAILED before any hashing): RegisterRequest `email` <= 254 (format email), `password` 12..128; LoginRequest `password` 1..128; VerifyRequest `token` 20..200.
- **Opaque tokens** (refresh + email verification) (`identity/internal/application/OpaqueTokens.java`): 32 bytes from `SecureRandom`, **Base64url without padding** (43 chars). Stored as **lower-case hex SHA-256 of the UTF-8 token string** (64 chars) in `refresh_tokens.token_hash` / `email_verifications.token_hash` (both unique). Raw token never stored.
- **Email verification**: row `(id v7, user_id, token_hash, expires_at = now + 24h, used_at)`; lookup by hash with `PESSIMISTIC_WRITE`; usable iff `used_at is null && expires_at > now`; any failure -> 400 VALIDATION_FAILED field `token` "Invalid or expired token". Success marks used, sets `users.verified=true`, publishes `UserVerified`. Register always answers 202 `{"message":"If this address can be registered, a verification message has been sent."}` (same for existing emails; race on unique email swallowed).
- **Refresh token rotation** (`Login`, `Refresh`, `Logout`, `domain/RefreshToken.java`):
  - Login: new family `family_id = UUID.randomUUID()` (v4), token row id v7, `expires_at = now + 14d`.
  - Refresh (`@Transactional(noRollbackFor = Unauthenticated)`): missing/blank -> 401; lookup by hash `FOR UPDATE` (serialises concurrent refreshes); unknown -> 401.
    If `replaced_by != null` (already rotated) => **reuse detected**: `update refresh_tokens set revoked_at = now where family_id = ? and revoked_at is null`, publish `RefreshTokenReuseDetected(userId, familyId, now)`, warn log, 401 (revocation committed).
    Else if revoked or `expires_at <= now` -> 401. Else insert successor (same family, same user, new hash, `expires_at = now + 14d` – sliding, no absolute family cap), set `current.replaced_by = successor.id`, issue new access token.
  - Logout: hash lookup; if found revoke whole family; always 204 and clears cookie.
  - Cookie: `refresh_token=<token>; Path=/api/v1/auth; Max-Age=<ttl seconds>; Expires=...; Secure; HttpOnly; SameSite=Strict`; logout sets value `""` with `Max-Age=0`. Token responses also send `Cache-Control: no-store`.
  - Body `{"accessToken": "...", "tokenType": "Bearer", "expiresIn": 600}`.
- **JWT (own issuing)** (`AccessTokenIssuer`, `JwtKeys`, `IdentityConfig`): ES256 (P-256) via Nimbus; header `{"alg":"ES256","kid":<kid>}`; claims only `sub` (Ledgerly user UUID), `iat`, `exp` (= iat + 10m), `jti` (random v4). No `iss`, no `aud`, no roles/email.
  Keys: `ledgerly.auth.jwt-private-key` = PKCS#8 EC private key, `jwt-public-key` = X.509 SubjectPublicKeyInfo; PEM or bare Base64 (PEM armour lines `-----...-----` and whitespace stripped, then standard Base64 decode).
  **kid = RFC 7638 JWK thumbprint (SHA-256, Base64url)** of the public key (`keyIDFromThumbprint()`), stable across restarts; generated keys (local/test) use a random v4 kid.
  Verification: only ES256 accepted, key from local public JWK (no HTTP), `JwtTimestampValidator` with 30s clock skew using the app Clock; no issuer/audience checks.
  JWKS at `GET /.well-known/jwks.json` = `{"keys":[<public JWK: kty EC, crv P-256, x, y, kid>]}`.
- **Keycloak mode** (`KeycloakResourceServerConfig`, `ExternalSubjectJwtConverter`, `ExternalIdentityProvisioner`): issuer discovery from `issuer-uri` lazily; validators timestamp(30s skew) + issuer + `aud` contains `ledgerly-api`; IdP unreachable -> 401 (BadJwtException). `sub` rewritten to Ledgerly user id; original kept as claim `external_sub`.
  Match by `users.external_subject`; else by normalised email only if `email_verified=true` and the local account has no external subject (links it); else creates user (v7 id, no password). Missing email -> 401. Publishes `UserRegistered` / `UserVerified` accordingly.
- **Idempotency keys**: raw key stored (not hashed); request hash = hex SHA-256 of record `toString()` (see 3.4).
- **Receipts storage keys**: `receipts/<UUIDv4>` on upload; quarantined object moved to `quarantine/<UUIDv4>` and `receipts.storage_key` updated. Imports: `imports/<UUIDv4>`. Single bucket (`ledgerly.storage.s3.bucket`). Original file name is never part of a key.
- **sha256 of receipts**: lower-case hex (64 chars) of raw file bytes (`HexFormat.of().formatHex`), column `receipts.sha256 varchar(64)`; unique `(expense_id, sha256)`; `possible_duplicate` = same sha256 on another expense in the team.
- **Download names** (`receipts/internal/application/FileNames.java`): drop everything up to last `/` or `\`; split at last `.` (if index > 0); base: replace `[^A-Za-z0-9_-]` with `_`, strip leading `[_-]+`, cap 80 chars, blank -> `receipt`; extension from detected type: pdf/jpg/png else `bin`.
  Display name (stored `original_name`): remove `\p{Cntrl}`, strip, empty -> `receipt` (imports: `import.csv`), cap 255.
- Content type detection: Apache Tika `new Tika().detect(InputStream)` on bytes only; allowed `application/pdf`, `image/jpeg`, `image/png` (else 415 "Only PDF, JPEG and PNG files are accepted"); empty file -> 400 field `file` "The file is empty".

## 5. Background processes

### 5.1 Event publication registry / outbox (Spring Modulith 2.1.2, JPA starter + Jackson serialisation)
- Table `event_publication` (V7, Modulith schema v2): `id, listener_id, event_type, serialized_event, publication_date, completion_date, status, completion_attempts, last_resubmission_date`.
  A row per (event, transactional listener) is written in the publisher's tx; completed when the listener returns normally. Completion mode not configured => default **UPDATE** (sets `completion_date`/status, rows kept until purged).
  `event_type` = Java FQCN (e.g. `com.ledgerly.teams.events.TeamEvent$TeamCreated`); `serialized_event` = Jackson JSON of the record (id wrappers serialise as `{"value": "<uuid>"}`). A Rust port need not be byte-compatible here unless in-flight rows must survive cutover (drain the registry before switching).
- `spring.modulith.events.republish-outstanding-events-on-restart: true` -> incomplete publications are re-delivered at startup.
- `EventMaintenance` (`J/shared/config/EventMaintenance.java`, `@EnableScheduling`, on unless `ledgerly.events.resubmit-enabled=false`):
  - `resubmitStuckEvents`: fixed delay `${ledgerly.events.resubmit-interval:PT1M}`, initial delay 1 min; resubmits incomplete publications older than **2 minutes**.
  - `deleteOldCompletedEvents`: cron `0 17 3 * * *` (03:17 daily, server TZ); deletes completed publications older than **7 days**.
- Delivery semantics: at-least-once; listeners are idempotent (audit `on conflict (event_id)`, scan checks PENDING_SCAN, import runner checks status, cleanup deletes what is left).
- `@ApplicationModuleListener` = `@Async` + `@Transactional(REQUIRES_NEW)` + `@TransactionalEventListener(AFTER_COMMIT)`. Async executor runs on virtual threads (`spring.threads.virtual.enabled`).

### 5.3 Receipt upload and async scan
Upload (`receipts/internal/application/UploadReceipt.java`, no outer tx):
1. `ExpensesFacade.requireCanChangeReceipts` (before reading the body).
2. Stream to temp file through `CappedInputStream(maxUploadSize)` + SHA-256 `DigestInputStream`; Tika-detect type from the temp file.
3. size 0 -> 400; type not allowed -> 415; same sha256 on this expense -> 409 RECEIPT_DUPLICATE; compute `possibleDuplicate`.
4. `storage.put("receipts/<v4>", temp, type)`.
5. Tx: insert receipt (`scan_status = PENDING_SCAN`, id v7, `created_at` = clock), publish `ReceiptUploaded(id)` and `ReceiptEvent.Uploaded`; unique violation -> delete object, 409; any other failure -> delete object, rethrow. Temp file always deleted.
6. Response 202 with receipt (status PENDING_SCAN).

Scan (`ScanReceipt.scan`), states `PENDING_SCAN -> ACCEPTED | QUARANTINED`:
- Load receipt; if missing or not PENDING_SCAN -> return (idempotent).
- Open object, `MalwareScanner.scan`. `ClamAvScanner` (`receipts/internal/infrastructure/ClamAvScanner.java`): TCP to clamd (connect timeout 2s, read timeout 30s), send `zINSTREAM\0`, chunks of `<4-byte big-endian length><bytes>` (8192-byte buffer), terminator `00 00 00 00`; read reply until NUL, ASCII, strip;
  `^stream: OK$` -> Clean; `^stream: ([A-Za-z0-9._+-]{1,200}) FOUND$` -> Infected(sig); anything else -> IOException.
  Retries: `@Retryable(includes = IOException, maxRetries = 3, delay = 500ms, multiplier = 2)` -> up to 4 attempts, waits 500/1000/2000 ms (note: same, partially consumed InputStream is reused on retry – a Java quirk; a port should reopen the object per attempt).
- Any failure -> warn log, throw `IllegalStateException` -> publication stays incomplete -> re-delivered by resubmit job (>2 min old, every minute) or at restart; receipt stays PENDING_SCAN.
- Clean: tx { status ACCEPTED; publish `ReceiptEvent.Accepted` }.
- Infected: tx { status QUARANTINED, storage_key = `quarantine/<v4>`; publish `ReceiptEvent.Quarantined` }; counter `ledgerly.receipts.quarantined`; warn log with signature; then `storage.move(old, quarantineKey)` (copy + delete; failure leaves stray object, row already quarantined).
- Only ACCEPTED receipts are downloadable (others 404); download = presigned GET valid 5 min, response `{url, expiresAt}`.
- Submit rule uses `ReceiptChecks`: >=1 ACCEPTED and 0 PENDING_SCAN.

### 5.4 Import flow (`J/imports/`)
Upload (`UploadImport.execute`), sync, returns 202:
1. `TeamsFacade.roleOf` -> 404 if not teammate (any role may import).
2. Quick daily-limit check: count `import_jobs` with `team_id, user_id, created_at >= start of UTC day` >= `maxImportsPerDay` (5) -> 429 RATE_LIMITED "At most 5 imports per team per day", `Retry-After` = seconds to next UTC midnight.
3. Copy upload to temp via `CappedInputStream(maxUploadSize)`.
4. Inspect: strict UTF-8 decode (malformed -> 415 "The file must be UTF-8 text"); header (BOM `﻿` stripped) split on `,`, each stripped+lower-cased must equal `date,merchant,amount,currency,category` or `+ ,note` (else 400 field `file` "The first line must be: date,merchant,amount,currency,category[,note]"); NUL byte in any line -> 415 "The file is not a CSV text file"; count non-blank lines; > maxImportRows -> 400 "At most 10000 rows per import"; 0 -> 400 "The file has no data rows"; empty file -> 400 "The file is empty".
5. `storage.put("imports/<v4>", temp, "text/csv")`.
6. Tx: `select pg_advisory_xact_lock(hashtextextended('import:<teamId>:<userId>', 0))`, re-check daily limit, insert `import_jobs` (id **v4**, status `QUEUED`, `total_rows`, `imported_rows 0`, `created_at` = clock), publish `ImportQueued(id)`. On failure after store -> delete object.
7. Response: 202, Location, body from `GetImport` (`{id, status, totalRows, importedRows, skippedRows, errors:[{line, code, message}], errorsTruncated}`).

Job (`ImportRunner` after commit, async, tracked in event registry):
- `run(id)`: status `QUEUED` -> `JobOperator.start(job, params)`; `FAILED` -> restart from last execution; otherwise no-op. Launch exception -> mark FAILED.
- Job params: `importId` (identifying), `teamId`, `userId`, `storageKey` (non-identifying). Spring Batch metadata in `BATCH_*` tables.
- `ImportJobListener.beforeJob`: `status='RUNNING', started_at = coalesce(started_at, now), finished_at = null`.
- Step `importStep`: chunk size = `maxBatchSize` (100), fault-tolerant, skip `RowRejected` and `FlatFileParseException`, skip limit `maxImportRows`.
  - Reader: `FlatFileItemReader` over `StorageResource` (reopens object each time; restartable), UTF-8, skip 1 header line, `DelimitedLineTokenizer(",")` with quote `"`, `SimpleRecordSeparatorPolicy` (one physical line per record). Line numbers: header = 1.
  - Processor `RowProcessor`: blank row -> filtered (no error). Columns 5 or 6 else `COLUMN_COUNT` "Expected 5 or 6 columns but found N"; `date` ISO `LocalDate.parse(strip)` else `DATE_INVALID` "date must look like 2026-11-05";
    currency `strip().toUpperCase()` else `CURRENCY_INVALID` "Unknown currency code"; amount `new BigDecimal(strip)` + Money rules else `AMOUNT_INVALID` ("amount is not a number" or Money's message); category `strip().toUpperCase()` else `CATEGORY_INVALID` "category must be one of TRAVEL, MEALS, OFFICE, SOFTWARE, OTHER";
    note = 6th column stripped if non-blank; merchant = `strip()`; then `ExpensesFacade.validate` -> `VALIDATION_FAILED` "<field>: <message>".
  - Skip listener: read parse error -> `PARSE_ERROR` "The line could not be read as CSV"; other process failures -> `ROW_INVALID` "The line could not be imported"; inserts into `import_row_errors` `on conflict do nothing` (message truncated to 500 chars); counter `ledgerly.imports.rows.skipped`.
  - Writer: `ExpensesFacade.createDrafts(team, user, chunk)` + `imported_rows += n`, same chunk tx (each chunk commits independently).
- `afterJob`: `status = COMPLETED|FAILED`, `finished_at = now`; on COMPLETED delete the CSV object (failure warns); publish `ImportCompleted(team, user, importId, imported_rows, errorCount, failed = !completed, now)`; log "Import {} finished: {}".
- `GetImport`: visible to the uploader and team OWNERs; others (and non-members) 404; errors ordered by line, max 1000, `errorsTruncated = skipped > shown`.
- Import statuses: `QUEUED, RUNNING, COMPLETED, FAILED`.

### 5.5 Other time-based behaviour (no schedulers)
- Invitation expiry computed on read (no job). Idempotency keys expire by `expires_at` filter (no purge). Refresh/verification tokens never purged. Rate-limit buckets expire from Caffeine after 2h idle.
- Graceful shutdown: `server.shutdown: graceful`, 30s per phase.
